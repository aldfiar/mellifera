# GLOSSARY

Canonical vocabulary for mellifera. Definitions only — design notes live in specs and proposals.

- **Artwork** — the image a surface shows for an element or series: the stored artwork override, else the composed poster, else the frame-grabber thumbnail, else the placeholder. The served `artwork` field composes the first two legs server-side; the thumbnail leg composes client-side (the detail surface's hero fallback). Composed at read time, never persisted. The override may pin a source poster, the thumbnail, or an uploaded image; Refresh never touches it.
- **Client (enrichment context)** — an HTTP consumer of the mellifera API (the SPA or any REST caller) that can *trigger* enrichment of an entity. The server always executes enrichment fetches (fetch mode A). Not the go-plugin host (that is always mellifera core), and not a mode B credential holder.
- **Poster** — an artwork image supplied by a metadata source: the plugin records a URL under `poster` in its own namespace; the core downloads and caches the bytes server-side for serving. Distinct from the frame-grabber thumbnail (locally generated).
- **Dormant source** — a metadata source whose operator gate (module- or Collection-scope preference) disables it: it derives nothing (excluded from the enrichment chain and its extras) and composes nothing (excluded from the display title walk), while its stored namespace, provenance and view entries stay byte-identical and are never purged. Re-enabling restores derivation through the enrichment queue's wake — no rescan, no lifecycle transition.
- **Fetch mode A / mode B** — who executes a plugin-built RequestSpec: A = the server; B = a client holding the upstream credentials (contract-supported, not built).
- **Enrichment queue** — the derived set of pending (row, plugin) work, computed from rows + namespaces + the failure ledger. There is no queue, claim, or lease table; work is never stored, only derived.
- **Namespace** — the per-plugin subtree an enrichment plugin owns inside an item/series document (`sources.<plugin_id>`, plus its `_provenance` / `_view` entries). A plugin may write only its own namespace.
- **Recommendation score** — the read-time number the server orders collection grids, the continue rail, and next up by: context bonuses (in-progress 1000, new-episode 500) plus a capped tag-interest component, ties falling back to display_name then id. Computed at read time, never persisted; `sort=path` restores path order, and photo libraries always keep path order regardless of score.
- **Refresh** — an explicit operator action re-running one plugin's enrichment on a row or library: the plugin's namespace, provenance and view entries are removed and its ledger row cleared, and the existing derivation re-runs it. Replaces the namespace wholesale; user title overrides are untouched.
- **Drifted row** — a row whose recorded provenance `plugin_version` differs from the running plugin's version. Computed on demand from documents; never stored. A drifted row is re-enriched automatically on detection (unless gated by cooldown, per-Collection disable, or module gate) — no operator consent step.
- **Deletion-pending** — the derived state of a namespace whose plugin is absent from the intended plugin composition. Never stored; emitted by derivation only after the delete-grace window (default 7d from process start) and cleaned through the queue (strip + ledger-row clear; identifiers survive; status unchanged). Data serves in place until deletion. Distinct from registered-but-unbound (dormant forever) and failed-to-load (fatal at boot).
- **Film (serial library)** — a direct video file inside a serial library handled by the film parse path (movie-shaped metadata); not a library type. A film's poster renders on library element surfaces only — its detail view keeps the generated thumbnail.
- **Collection** — the library itself (a registered root directory with its parser chain and options). Not a separate stored entity; every collection surface renders a library.
- **Subcollection** — the grouping level inside a collection, per library type: for serial libraries the series; for image libraries the album (depth-1 folder grouping). Not a stored entity.
- **Element** — an item (episode, film, tv record, image) as a member of its subcollection.
- **File-backed series** — a series row backed by a single video file rather than a directory (the default). Its path floor is the filename, so stem/rename/identity questions follow file rules, not directory rules.
- **Naming option** — the per-library display-naming setting (group style, element name template); absent fields fall through to the module default template. Stored as flat library columns, PATCHable.
- **display_name** — the server-composed display name of an item or series, served on the wire and never persisted: title override → composed name (facts + resolved series + template) → verbatim `_view.title` → empty string. Never the raw filename, never a fabricated value.
- **Unidentified** — the state of an element or series whose served display_name is empty or equals its path-derived name (final filename or directory segment). A naming-floor state, not an enrichment state — distinct from drift or failure. Viewer surfaces render the extension-less stem; menu-bearing surfaces add the muted "Not identified" marker.
- **Match-time inputs** — what an enrichment plugin's Match stage may see of "parser data": the document's scanner-fact `parsed` region and the document's identifiers (e.g. a previously resolved `shikimori_id`). Derived parser facts (titles, seasons) live in `sources.<parser>` and never reach Match; a metadata plugin re-derives what it needs from raw scanner facts.
- **Dormant source (per-Collection disable)** — a metadata_source excluded from enrichment derivation for one Collection. Its existing namespace is retained and keeps serving; disable never purges (purge is the explicit Refresh action). Distinct from a module-level `enabled: false` binding (all-Collection) and from CLIENT auth-mode gating.
- **Watched (completed)** — an item whose progress position has reached ≥ 90% of its stored duration, recorded exactly once in the completion ledger (`watched_items`); repeat writes and rewatches are no-ops. A completed item skips the in-progress bonus and feeds tag learning via the recs janitor task.
- **User** — a personal account: a named principal that authenticates by password (argon2id, checked only at session mint) and carries a role (user | admin); belongs to any number of groups. Not a device.
- **Group** — an admin-composed named scope: member Collections with display positions (overlap allowed; order conflicts resolve min-position, tie by group id) plus per-collection source mutes in a schema-versioned JSON document. Says WHAT is visible and HOW it is enriched; membership says WHO.
- **Role** — what a principal may DO (admin reaches operator surfaces; a user-role principal routes as a client). Orthogonal to groups, which scope what it may SEE.
- **Principal** — the authenticated caller a credential resolves to at the auth seam (env admin token, device token, user session); carries its role and its resolved Viewer.
- **Viewer** — the resolved visibility context threaded through every content read as an explicit trailing parameter: the visible-library-id set plus per-source mutes; scopes: system (internal callers, unfiltered), admin (all), user (group-filtered), legacy-device (today's client scope). The zero Viewer hides everything — fail closed.
- **Grant** — visibility derived from group membership: user principals are grant-based (default hidden); legacy principals (admin token, unbound devices) keep today's see-all. The planned per-Collection `restricted` floor composes into the same resolution and is never lifted by membership.
- **Credential** — a bearer secret resolved at authN, stored hash-only at rest (SHA-256 for tokens; the env admin token is never stored); kinds: admin (env), device (pairing), session (login).
- **Search index** — the RAM read model behind `/search`: per-entity entries (the composed served name plus the title walk's unpicked alternates) folded once at write time with the shared transform (Unicode casefold + bidirectional ё→е, applied again at query time), matched in tiers (composed-prefix > composed-substring > alternate), bounded 8+8 series + item ids with an alphabetical tiebreak. Built from store rows at boot, reconciled on change pokes and a 60 s drift check (two-part epoch), never persisted. It decides only WHICH ids match — rows and DTOs compose live api-side, so a stale index can lose freshness but never lie about a name.
- **Facet** — a served per-library aggregate over the grids' filter dimensions (genres/kind/status): the distinct values with their counts, computed at rebuild time by running the SAME naming resolver the About block serves — facets can never diverge from About by growing a second walk. Served on `GET /libraries/{id}/facets`; a key no document's resolved About block carries is absent, a count-0 value is omitted, photo libraries serve empty lists. Narrowed per request by the additive facet filter params on /series and /items.
- **Continue row** — one row of the home continue rail (`GET /api/v1/home`): the series the in-progress item anchors to (served id, display name, query-time artwork) beside its resume point and the next-episode offer. Ordered by the recommendation score (desc, updated_at tiebreak), capped at 50 rows server-side, read through the caller's Viewer so invisible-library rows never serve. A row whose item carries no series anchor (film or tv item) serves empty series fields and never carries next.
- **Pack** — the packaged HLS build of an item (manifest + master + variant playlists) that a playback descriptor resolves to over direct play. The Android TV APK is its immutable-asset sibling: dropped into the same assets tree as a versioned `mellifera-tv-<version>.apk` and served under `/apk`, where filename↔bytes identity (no-clobber drop) makes the filename the immutable cache key and the SPA's version label.
- **Beacon** — the fire-and-forget failure/debug telemetry posture of mellifera clients: an event is POSTed (playback-events beacons; `POST /debug-events` for debug telemetry) and the sender never waits on or reacts to the answer beyond best-effort backoff. Server side it is one structured INFO line per accepted event under a per-IP fixed window (30/min) answering 429 silently, with free-text detail truncated to a 256 bound; client side query strings are stripped before send (INV4 — no token or URL material in any event).
