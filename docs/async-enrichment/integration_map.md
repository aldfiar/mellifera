## Behavior-change impact on existing flows

- **`POST /libraries/{id}/scan` semantics (load-bearing, backward-compat):** previously BLOCKED until every item was enriched (`handlers.go:97` → `scan.Run` → inline enrich). After B1 it returns after discovery+identify+persist (items `pending`); enrichment completes async. **The response shape (`scan.Result{Discovered,Persisted,Warnings,...}`) is unchanged** — only the timing. A client polling `?status=` observes items moving `pending→ready`. This is the one user-visible behavior change; it is the POINT of the feature (AC-async). Deprecate-don't-delete: the serial `enrich.Enrich` path is preserved (worker-internal / sync-testable).
- **Re-scan (PutItem upsert):** an unchanged file re-scanned → upsert preserves `id`/`created_at`, refreshes mutable fields (`items.go:51-63`). B1 adds: a changed file → `stale→pending` (re-enrich). Detection basis: compare the refreshed document/identity against the prior; if changed, advance `stale`. (Minimal B1: status set to `pending` on re-scan so the queue re-derives; full change-detection via mtime/size is a refine — see architecture_review R-states.)
- **Crash/restart:** in-memory queue + leases are gone on restart; `Start` re-derives pending from `items`; exhausted ledger pairs are NOT re-derived into a loop. Per-session in-memory retry counters reset (a failing entity resumes from its last ledger state). (AC-ledger.)
- **Plugin crash isolation (unchanged):** a crashing enricher subprocess is observed by the worker as a failed RPC; the worker soft-fails/requeues that source (arch §0 #2, `plugin.Manager` monitor restarts the subprocess at `lifecycle.go:46,172`). The queue never aborts on one plugin.

## External boundary changes

**None for B1.** B1 uses only the existing local `tv-parser` (no upstream HTTP, no new deps). External HTTP (TMDB), rate-limiting, response caching, and `AuthContext` secret injection are **B3** (outlined). The §4.4 per-RPC timeouts bound the lease-hold window (contracts `LeaseTTL`); idempotency for B1 is inherent (re-derivation + reset-on-success). N/A cells are intentional, not blank.
