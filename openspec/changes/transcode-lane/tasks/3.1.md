# 3.1 Codec-superseded lazy repack — existing HEVC builds heal on play

## Goal

A complete, current-layout build whose recorded codecs name HEVC repacks
ONCE on the next play while the transcode knob is on, through the exact
one-enqueue path pack-manifest-audio landed — no sweep wave, no second
mechanism — and the arm closes itself when the replacement (avc1) lands.

## Context pointers

- design: design.md D5 (the arm, the declined sweep wave, the fail-open)
- code: `cmd/mellifera/playback.go` — pack-manifest-audio's lazy repack
  decision in the play verb (their task 3.1: state complete + nonce + no
  build-generation marker → PackGate pre-check → one EnqueuePack); the
  namespace doc (`doc["streams"]`) carries `codecs` (their D2 record) and
  `master` (their marker) — this arm reads the RECORDED codecs only (first
  entry prefix `hvc1`/`hev1`), never re-composes from source facts
- specs: packaged-playback delta "Lazy repack of legacy-layout builds"
  (the superseded arm + the fail-open + the closed-arm scenarios)

## Done when

- The decision carries BOTH arms: legacy-layout (no marker — theirs) and
  codec-superseded (marker present + recorded hevc + knob on — this task);
  both ride the same PackGate pre-check and the same one-enqueue path.
- Knob off: the superseded arm is inert — the gate pre-check answers
  `codec_not_opted_in`, ONE INFO refusal line, no enqueue, no state change,
  no ledger row (the existing gate-closed test extended to this arm).
- Fail-open: absent/uncomposable recorded codecs → no enqueue on this arm.
- New cmd tests: hevc-codecs build enqueues exactly one repack under the
  knob; a second play after the avc1 replacement lands enqueues nothing;
  plays during the run are lease-absorbed (their precedent asserted for
  this arm); the legacy-layout arm's behavior is unchanged (their tests
  stay green).
- No new exported symbol; the arm's helper is unexported cmd code.

## Audit

Not an audit task.

## Out of scope

- The transcode build itself (group 2) — the enqueued repack lands as a
  transcode because the gate + mode decision say so, not because this arm
  forces a mode.
- Any descriptor projection of "superseded" (declined — design D5/Risks).

## Handoff

- First-play UX: the descriptor answers the current hvc1 build until the
  repack lands — the device banner fires once, honestly. Do not add
  read-side state to mask it (declined in design).
- The recorded-codecs read is the namespace field only (`doc["streams"].
  codecs`); if pack-manifest-audio renames the field at GATE 2, follow the
  merged living spec — the arm's contract is "the recorded record's first
  entry", never a source-facts recomposition.
