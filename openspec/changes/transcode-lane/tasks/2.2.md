# 2.2 The build-mode branch — the lane encodes when (and only when) the knob says so

## Goal

`Pack` runs the transcode branch exactly when `Service.Transcode &&
videoTranscodable(facts)`, producing a normal build (same layout, same
publish machinery, same downstream everything); knob-off args are
byte-identical to today.

## Context pointers

- design: design.md D2 (the branch + the declined alternatives), D3 (the
  output is a normal build), D7 (the invariant amendment)
- code: `internal/stream/pack.go` — the three arg sites (`:245-248`,
  `:274-277`, `:299-335`: `-c copy` at each; head args `-map 0:v:0
  -map 0:a:0` + voiceover maps + hls flags), the single exec site
  (`:365`, `exec.CommandContext(pctx, s.FFmpeg, args...)`),
  `variantLayout` (`:111`); `internal/stream/service.go` — `Service`
  (`:57`, gains the `Transcode` field), `Pack`'s entry (facts in hand);
  `internal/stream/doc.go` — the no-encode invariant line to amend
- specs: packaged-playback delta "Remux-only pack lane" (the transcode
  exception + the knob-off pin), "Pack flow observability" (mode on the
  publish line — task 3.2 owns the line, this task's mode decision feeds it)

## Done when

- The mode decision reads `videoTranscodable` (task 1.1's helper — one
  fact, two readers); no second copy of the codec set anywhere.
- The three arg sites branch: video encoded per the task-2.1 builders
  (`-c:v libx264 -preset veryfast -crf 22 -pix_fmt yuv420p`), each audio
  output per the per-stream rule (aac/mp3 copy, else `-c:a aac`), mapping
  and hls flags unchanged.
- The existing pack suite (`TestPackLane`, `TestHeadFirst`, …) stays green
  UNTOUCHED — knob-off byte-identity is pinned by absence of edits to it.
- `doc.go`'s invariant names the exception: encode ONLY in the knob-gated
  transcode branch; the direct floor stays unconditional; remux is the
  default when the knob is off.
- A real-ffmpeg test transcodes `internal/stream/testdata/
  tiny_hevc_aac.mp4` into a valid fMP4-HLS build (validate passes, init
  carries `avc1`, the aac track stream-copied, head-first partial publish
  serves the master first).
- `internal/stream` still counts 7 exported symbols.

## Audit

Not an audit task.

## Out of scope

- The pure arg builders and their table (task 2.1).
- The publish line's mode field + progress lines (task 3.2).
- Any serve/validate/tokenize change (all layout- and codec-agnostic).

## Handoff

- The committed fixtures: generate ONCE on any host whose ffmpeg has
  libx265 (`ffmpeg -f lavfi -i testsrc=size=160x90:rate=12:duration=2 -c:v
  libx265 -pix_fmt yuv420p10le -tag:v hvc1 -c:a aac -b:a 64k
  tiny_hevc_aac.mp4` and the ac3 variant with `-c:a ac3 -b:a 64k`), commit
  the binaries (a few KB each), and delete nothing — tasks 2.2 and 4.1
  both read them; test-time decode is native ffmpeg (no libx265 needed to
  RUN the suite; only libx264 for the encode, which the duties guard).
- If a host ffmpeg rejects a builder flag combination (e.g. an old
  libx264), the failure lands in the ordinary pack-failure contract with
  the F4 tail reason — surface it in the task notes; never silently swap
  encoder constants.
