# 4.1 Joint — real transcodes through the real server surface, no mocks

## Goal

The whole story over real ffmpeg processes and the real server: knob on →
HEVC item packs → H.264 build publishes in the master layout → descriptor
answers its codecs → exactly one build remains; knob off → today's honest
refusal; healing arm repacks an existing HEVC build.

## Done when

- (a) Knob on, hevc+ac3 fixture through the ordinary play flow: descriptor
  `preparing` → `hls`; the published build carries the composed master
  whose CODECS name `avc1` + `mp4a.40.2`; exactly one build directory
  after replacement; the captured log carries the flow lines with mode
  `transcode`, bounded progress lines, and NO token or play URL anywhere.
- (b) hevc+aac fixture: the aac track is stream-copied (recorded codecs
  keep `mp4a.40.2`; no audio encode).
- (c) Knob off: the hevc item answers `unsupported` +
  `codec_not_opted_in`, nothing enqueues, no ledger row — today pinned.
- (d) Seeded complete current-layout build with recorded hevc codecs:
  POST /play enqueues exactly ONE repack under the knob; the replacement
  carries avc1; the second play enqueues nothing.
- (e) mpeg4-ASP source: `codec_unsupported` under both knobs.
- `go vet`-clean; the joint is hermetic (t.TempDir, no network, no host
  state beyond ffmpeg).

## Audit

Not an audit task (this IS the @qa task — the qa: list names the joint
the QA tier owns; existence is enforced by this task's own verify).

## Out of scope

- New unit coverage in internal/stream or cmd (groups 1–3 own theirs).
- Any web/ or api surface assertion (no wire change exists to observe).

## Handoff

- If the host ffmpeg lacks libx264 the duty guard fails first — that is
  the honest outcome; do not weaken the guard to go green.
- The transcode of a 2-second fixture takes seconds; keep durations tiny
  so the joint stays fast. If `-preset veryfast` proves slow on CI for
  even tiny inputs, the fixture — never the production constants — is the
  dial.
