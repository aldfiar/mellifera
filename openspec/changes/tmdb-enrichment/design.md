# Design

## Context

The design input is the delivered layer-4 design (`/Users/aldfiar/projects/go/mellifera/.tmp/layer4-design.md`, Concern 1 + §1's serial bullet); the operator's scope ruling folds the ruled-out serial follow-up (OQ-4) into this change — films AND serials. Every seam below was re-verified against the live worktree tree at authoring time.

Ground truth this design lands on:

- **Fetch seam:** `internal/enrich/fetch.go` `fetchSource` validates and executes specs; `resolveVariables` (fetch.go:281) rejects every `redacted_ref` with `errRedactedRef` (fetch.go:33) — the `client:` Mode-B hook stays contract-present, unbuilt. `chain.go:188-190` passes an EMPTY `AuthContext{}` to BuildRequest (the D-7 comment names exactly this change).
- **Relay shipped:** `chain.go` carries `relayScope`/`handOff`/`buildPlan` + `outcomeDeferred`; `internal/enrich/relay.go` owns purposes `enrich|search`, `Consult`, and ingest; `internal/enrich/search.go` `searchOverRelay` rides the same path. `buildPlan` resolves variables through the SAME `resolveVariables` — so a spec carrying a `redacted_ref` returns nil today and a TMDB network-class failure would skip the relay path until the substitution seam learns `server:` (flag 5).
- **Registry:** `internal/module/registry.go` seeds tmdb in the TV module at priority 3, `auth_mode: "SERVER"`, enabled (registry.go:109-111); the serial module sits at `schema_version` 3 (registry.go:196) with guarded-upgrade precedent v1→2 (registry.go:44-46) and v2→3 (registry.go:54-56). `MetadataSourceBinding` carries `Options json.RawMessage` (registry.go:283) — but `internal/enrich` reads no binding Options today, and NO module-config write path exists anywhere (`UpdateModule`/`SetModule` absent repo-wide; plugin-admin's own Purpose reads "read-only observability surface") — flag 1.
- **Declarations:** the plugin's `Handshake` advertises `CapabilityDeclaration` (shikimori `pluginsvc.go:60-64`); `required_secrets` is proto field 6, unused. `Manager` retains the whole handshake response (`manager.go:111` field `handshake`), while capability ROUTING uses core-authored caps (`cmd/mellifera/main.go` `loadPlugin` literals) — flag 2.
- **Queueable:** `queueable` (queue.go:633) is `Enabled && AuthMode != "CLIENT"` — SERVER is already queueable; the ledger's closed status vocabulary (`exhausted|no_data|pack_failed|relayed`) has no unconfigured status, and this design adds none (decision D3).
- **Identify:** `PUT /series/{id}/identify` exists (router.go:566) over `Queue.IdentifySeries` (search.go:273, series-only); `ReenrichSource` (reenrich.go:59) is already row-generic (`rowIDs ...string`); `loadRow` (queue.go:673) is the item/series-agnostic loader. `PUT /items/{id}/identify` is NEW. The search passthrough `GET /admin/sources/{plugin_id}/search` (router.go:565) serves the SPA picker with zero new API.
- **Routing:** `routeEpisodeTitles` (episode_titles.go:49) routes a series run's `EpisodeTitle{episode, metadata}` entries onto episode documents by parse facts — the TMDB season contributions ride it unchanged.
- **Zero UI cost verified:** `web/src/components/metadata/Synopsis.tsx` renders the served `about` block; `web/src/components/watch/InfoColumn.tsx` renders cast; `web/src/lib/api.ts` types `MetadataAbout`/`MetadataCastEntry`/`MetadataEpisode` — all field-driven over the served projection; `openspec/specs/media-data-convention/spec.md` already names TMDB as an anticipated source. No web change, no convention delta.

Design assumptions of the input that NO LONGER hold exactly — carried as numbered flags, resolved here rather than silently deviated:

1. **OQ-5's "the admin already edits plugin config JSON" is false today.** The plugin-admin surface is read-only and no module-config write path exists (see ground truth). Resolution: this change ADDS the write surface — `Registry.SetBindingOptions` + `PUT /admin/modules/{module_id}/sources/{plugin_id}/options` — as OQ-5's store-backed home, plus secret-value redaction in served options (the aggregate serves options verbatim today; an api_key stored there would otherwise leak to the admin UI). That write is the Registry's FIRST mutation path — `ordered`/`byID` are Open-only-built and lock-free until now — so the change lands the Registry's first synchronization (an RWMutex or atomic snapshot swap guarding reads against the refresh) instead of a racy in-place cache update, proven by a `-race` concurrent-readers-plus-writer test (task 3.1).
2. **"Manager retains required_secrets from the handshake (it already parses declarations for capability routing)" holds only half-way.** Routing caps are core-authored; what the Manager retains verbatim is the handshake response (manager.go:111). Resolution: the accessor reads `required_secrets` from the RETAINED HANDSHAKE (the plugin-authoritative statement of what it needs), not from the routing caps.
3. **The design's `AuthContext{Mode: SERVER, ServerSecrets: {...}}` wording over-shares.** Substitution happens core-side at the executor (the design's own `resolveVariables` plan; the relay descriptor rule already requires resolved-before-handout), so the plugin never needs the values. Resolution: BuildRequest receives mode-only `AuthContext{mode: SERVER}`; values stay in the core — strictly narrower, same behavior, no secret exposure into the plugin subprocess.
4. **`SearchSpecsRequest` carries no auth field** (metadata.proto) — TMDB search specs carry the api key as a `server:` redacted ref resolved at the executor. Consistent with the design's plan; noted because the AuthContext rides BuildRequest only.
5. **`buildPlan` returns nil on any `redacted_ref` today** — until the substitution seam lands, a TMDB network-class failure would silently skip the relay path. `client-relayed-fetch`'s "server-authored descriptor" requirement ALREADY specifies the end state (including a server-resolved-secret scenario), so no relay spec delta; the resolver wiring rides this change's plumbing group.
6. **The tv seed's tmdb binding option `language: "en-US"` (registry.go:111) conflicts with RU-first.** The option is advisory config the enrich chain never reads; the plugin pins `language=ru-RU` per the Russian-first convention and the design input. No tv seed change (an unread cosmetic option is not worth a schema bump).
7. **Real series documents never carry `parsed.season` — the anchored series plan silently degrades to the movie path.** The design's anchored-series flow (D6, task 1.2's season law) assumed the Match input carries the series' season fact; it does not: the serial-parser writes season only into its document namespace (`sources["serial-parser"]["season"]`, plugins/serial-parser/parser.go:73/:91), the scanner's parsed stamp has none, and `reconstructBase` (internal/enrich/worker.go:135) feeds Match the parsed document alone — so the anchored series query carries `{tmdb_id}` alone, BuildRequest takes the movie path, the season extra never exists, and `ConvertResult.EpisodeTitles` never routes (QA wire-proven; the 5.1 joint receipt journaled red). Resolution (proto untouched, plugin contract untouched — core-side only): `reconstructBase` stamps the row's serial-parser namespace season fact into the parsed document handed to Match when present and >0, so task 1.2's existing anchor law works unchanged. Task 6.4.

## Goals / Non-Goals

**Goals:**

- The tmdb plugin enriches films (tv module, priority-3 slot) and serials (serial module, new priority-4 slot) through the unchanged 4-RPC chain + extras plan.
- SERVER-mode auth works end to end with zero secret exposure past the executor: store-backed config → required-secrets check → substitution → (relay) fully resolved descriptors.
- Unconfigured = dormant and visible: no ledger churn, the dashboard says why.
- Films gain `PUT /items/{id}/identify`; serial episodes gain names + overviews via the existing routing.
- Zero SPA edits; zero proto edits; zero relay-behavior edits.

**Non-Goals:**

- CLIENT-mode TMDB (user-pasted key, true Mode B) — stays a separate Phase-2 track; the `client:` scope remains the explicit unsupported error.
- Any new ledger status, any new queue table, any episode-document Match — the closed vocabularies and derived-queue invariants are untouched.
- Backdrop/logo artwork lanes, TMDB find-by-external-id, multi-season sweeps (only the series' own season fact is fetched).
- SPA changes of any kind (verified unnecessary); media-data-convention changes (the source conforms to it).

## Decisions

- **D1 — Plugin as a byte-pattern mirror of shikimori.** Same file set (main.go, pluginsvc.go, source.go match/buildrequest/convert, search.go, doc.go + per-area tests), same `sdk.Serve` both-services PluginSet, same compile-time `var _ sdk.MetadataSource` assertion, same upstream env seam pattern (`MELLIFERA_TMDB_UPSTREAM`, default `https://api.themoviedb.org/3` — shikimori's `MELLIFERA_SHIKIMORI_UPSTREAM` precedent, source.go:299-317) so the joint tests stub the upstream without network. Alternative rejected: in-process source — breaks the plugin-subprocess isolation the architecture pins.
- **D2 — Secrets live in the binding's options JSON (OQ-5), resolved against the handshake declaration.** The binding config (`MetadataSourceBinding.Options`) is the store-backed home the admin writes via the new endpoint; the required-secrets check = handshake names ∩ options keys. One home, no new table, no env story (OQ-5 rules env out for v1). Served options redact secret-named keys (flag 1's leak).
- **D3 — Unconfigured is dormant at derivation, not a ledger status.** The derivation-time queueability check grows the required-secrets-resolved conjunct for SERVER bindings (read-time, like gate-disabled dormancy — no row written, nothing to churn, no vocabulary change). The design's "(dormant semantics / flat cooldown)" offered both; dormant is the half that adds no state. The interactive producers run the same pre-action check — `SearchSource` before `SearchSpecs` executes AND `IdentifySeries` before any write (an unconfigured series identify must answer unavailable, never write-then-dormant) — answering the explicit unavailable error (api maps to 503) instead of a misleading 502 upstream_error. The INV2 seam follows the `ErrUnknownPlugin` precedent: the enrich-side sentinel (task 2.3), an api-local twin (task 3.4 — api imports no enrich package), and cmd's closures translating between them via `%w` wrapping (`newSearchClosure`/`newIdentifyClosure`, main.go:1153/:1172, the pattern at main.go:1158/:1181).
- **D4 — One substitution seam serves fetch, search, and relay.** `resolveVariables` gains the resolved-secrets input; `fetchSource`, the search executor, and `buildPlan` all pass it — the relay descriptor rule (client-relayed-fetch, already specced) is then satisfied by construction. Unresolved `server:` refs keep the explicit `errRedactedRef` (spec-class, never relayed); `client:` refs keep it unconditionally (flag 4/5).
- **D5 — Item identify generalizes over `loadRow` + the row-generic `ReenrichSource`.** `IdentifyItem` mirrors `IdentifySeries`'s anchor/strip/notify/lease semantics with the row loader instead of the series loader; the api route mirrors shapes and error mapping; `OnTitleChange` fires with the item id. Alternative rejected: overloading the series endpoint with a type param — two honest routes beat one branchy one.
- **D6 — Season contributions ride `ConvertResult.EpisodeTitles` untouched.** The plugin emits `EpisodeTitle{episode, metadata{title, description}}`; `routeEpisodeTitles` (episode_titles.go) does the rest — the contribution metadata carries BOTH convention episode fields because TMDB serves overviews (shikimori's requirement legitimately contributes title-only).
- **D7 — Seed v4 is the third guarded UPDATE.** `upgradeSerialConfigV4SQL` mirrors v2/v3 (`WHERE id='serial' AND schema_version < 4`), `serialConfigJSON` moves to `"schema_version": 4`, display block untouched (shikimori keeps the title/rating priority slots; tmdb contributes description/cast/episode groups — group-integrity merge gives tmdb exactly the groups its namespace carries).

## Interfaces

Cross-group contracts (the design.md home for them; nothing here restates existing code):

- **`sdk.MetadataSource` (existing, unchanged)** — `plugins/tmdb` implements all six RPCs; core chain, SDK adapter, and proto untouched.
- **`plugin.Manager.RequiredSecrets(pluginID) []string` (new, internal/plugin)** — reads the retained handshake's `CapabilityDeclaration.required_secrets`; unknown/undeclared → empty. Source of the required-names half of D2's check (flag 2).
- **`enrich.Deps.RequiredSecrets func(pluginID string) []string` (new closure, nil-safe)** — cmd wires it from the manager accessor; nil ⇒ every binding's required set is empty (legacy behavior byte-identical — flag scenario 3's anonymous-source law). Consumed by derivation's queueability conjunct and `runSource`'s auth-context leg.
- **`enrich` internal substitution seam (unexported)** — `resolveVariables` gains the resolved-secrets input; `fetchSource`, the search executor, and `buildPlan` thread it. No exported signature change beyond the Deps closure above.
- **`module.Registry.SetBindingOptions(ctx, moduleID, pluginID string, options json.RawMessage) error` (new)** — guarded UPDATE of the one binding's options inside the module row's config_json + cache refresh; unknown module or non-metadata binding → error (api maps 404/400). This is the Registry's FIRST mutation path — `ordered`/`byID` are Open-only-built and lock-free until now — so the method lands the Registry's synchronization (an RWMutex or atomic snapshot swap guarding Get/List reads against the refresh) rather than a racy in-place cache update (task 3.1's `-race` proof).
- **api Deps additions (all nil-safe closures, INV2)** — the options-write closure (route `PUT /admin/modules/{module_id}/sources/{plugin_id}/options`), `RequiredSecretsStatus func(moduleID, pluginID string) map[string]bool` (name→provided, per binding) feeding the aggregate's additive per-binding `required_secrets` verdicts + served-options redaction, `IdentifyItem func(ctx, itemID, pluginID, externalID string) (queued bool, stripped, deferred int, err error)`, and the unconfigured-source classification: an API-LOCAL sentinel twin classified via `errors.Is` to 503 — api imports no enrich package, so cmd's closures translate the enrich-side sentinel into the api twin via `%w` (the `ErrUnknownPlugin` pattern, main.go:1158/:1181).
- **Serial seed v4 JSON** — tmdb binding `{plugin_id: "tmdb", capability_id: "default", priority: 4, enabled: true, auth_mode: "SERVER", options: {}}` appended after shikimori; `schema_version: 4`; display block byte-unchanged.
- **Wire contract changes** — 2 new routes + aggregate fields ⇒ openapi (swag) + embedded-web regen task; no SPA source change.

## Risks / Trade-offs

- [Secret values stored in a config JSON the aggregate serves] → redaction requirement (secret-named keys omitted from served bytes) + admin-gated route; the api key stays a rotatable, low-value bearer (OQ-2 posture).
- [Relay descriptors necessarily carry the resolved key to relay principals] → already ruled and shipped (OQ-2: authenticated principals only, URLs redacted from logs/ledger); this change only makes the descriptors actually resolvable (flag 5).
- [Unconfigured binding silently invisible] → per-binding required-vs-provided verdicts are the visible "needs config" state (OQ-5 — judged per module binding, not per plugin: tmdb binds the tv module at priority 3 and the serial module at priority 4 with independent options); dormancy read-time so a later write configures on the next derivation without wakes.
- [Multi-season serials enrich only the anchored season] → accepted: the season fetch derives from the document's own season fact; other seasons keep parser titles (honest absence), a later identify/refresh can re-anchor.
- [TMDB rate limits under sweeps] → `min_interval_ms` 250 through the existing FetchGate slot (TMDB allows ~50 rps; the gate paces per plugin).
- [Search/identify on an unconfigured source] → explicit 503 unavailable with the missing-config reason, never a misleading upstream error.

## Migration Plan

Deploy = ship the binary + core. The serial seed promotion is a guarded, idempotent UPDATE: fresh stores INSERT v4 directly; v3 rows pass through on first open; re-opens are no-ops; no other module row is touched; rollback of the plugin leaves dormant seeded slots (the registry's existing unloaded-plugin semantics — derivation skips, nothing queues). There is no table migration and no document rewrite: tmdb namespaces appear on the next derivation per pair, and stripping is the existing explicit identify/refresh path.

None material. The two wording-level resolutions the input left open (mode-only AuthContext — flag 3; dormant-not-ledger — D3) are recorded as decisions above, and both preserve the specced behavior.
