# 1.3 Pack-lane rule version + the lazy re-heal gate

## Goal

The success persist writes the pack-lane RULE VERSION (`master: 2`) and
the lazy re-repack gate reads versions — boolean-true as v1, numbers as
their version, stale iff older than the current constant — so every
previously-packed build re-heals lazily (the known one-play-lag wave),
once, through the existing enqueue path and lease.

## Done when

- The success persist writes `master` as the number 2; failed docs stay
  marker-free (the existing enrich test keeps pinning that).
- The gate predicate: absent → stale (version 0), boolean true → stale
  (version 1) under the current constant 2, number 2 → current (no
  enqueue), number 3 → current (no enqueue — a FUTURE rule must not
  re-heal builds written by an older constant... pinned as: version ≥
  current never enqueues), gate-closed → one INFO refusal line, no
  enqueue, no state change (unchanged).
- Both call sites covered: the descriptor-GET trigger and the play verb
  enqueue exactly once per stale build, lease-absorbed while running.
- The pma joint stays green with its mirror and seeds re-based (a v1
  seed enqueues exactly one repack; the repacked build carries the
  version record; a version-2 seed never enqueues).

## Handoff

- JSON decoding shapes namespace numbers as float64 — read the version
  through a `case float64` (or a numeric assertion), never a raw `int`
  type-assert, or every recorded version reads 0 and the wave loops.
- The constant lives in enrich so the WRITER owns the shape; do not
  import stream from enrich (the PackItem seam boundary) and do not
  duplicate the constant in cmd/mellifera.
