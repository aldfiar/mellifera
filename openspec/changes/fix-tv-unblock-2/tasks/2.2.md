# 2.2 SPA direct-floor refusal

## Goal

An MSE-less device facing a rendition-layout descriptor refuses honestly
— the classified banner + one beacon, no mount — instead of silently
mounting video-only. The flat single-audio direct floor stays working and
stays pinned.

## Context pointers

- design: design.md Interfaces 6 (the refusal contract) and D6 (the
  capability-probe surface pattern; the rejected alternatives)
- code: `web/src/components/playback/Player.tsx` — the lane gate
  (`:164`), the probe dead-end pattern (`:176–192` — banner shape,
  `setError` + `beacon` + return), the direct floor (`:219–238` — the
  refusal slots BEFORE `video.src` is set), `errorText` (`:453–477` —
  the new wording branch); `web/src/lib/api.ts` — `PlaybackDescriptor`
  (`:287–317`, the additive optional-field precedent)
- pins: `web/src/components/playback/Player.test.tsx` — the red
  lane-selection test (`:231–246`, mechanism-free; align its fixture
  with `layout: "rendition"` — `hlsDescriptor({ layout: "rendition" })`,
  do NOT mutate the shared `HLS_DESCRIPTOR`), the MSE-less fallback pin
  (`:207–213`, re-bases on `hlsDescriptor({ layout: "single-variant" })`
  — the flat path stays pinned mounting the native src), the MSE-present
  lane-selection test (`:222–229`, must stay green untouched)
- specs: web-ui delta "Video playback in the SPA" — the refusal rule and
  the two new scenarios

## Done when

- MSE-less + `layout: "rendition"`: banner renders (role=alert, the
  rendition-layout-unsupported class), exactly ONE
  `sendPlaybackEvent` call (mode hls, phase video-error, code
  rendition-layout-unsupported, detail "rendition"), zero hls instances,
  and the `<video>` carries no src — the red test turns green.
- MSE-less + `layout: "single-variant"` and MSE-less + layout-absent:
  the native src mounts exactly as today, zero beacons (the re-based pin
  + a new absent-layout case if the pin's fixture doesn't already cover
  it).
- MSE-present + rendition: the hls loader mounts as usual (the
  lane-selection test stays green).
- `PlaybackDescriptor.layout?` typed; `api.test.ts` pins the shape;
  `tsc --noEmit` clean.

## Audit

Not an audit task.

## Out of scope

- The descriptor server side (task 2.1) and the embedded-build regen
  (task 2.3).
- Any MSE-check weakening (`typeof MediaSource`) or an hls.js attempt
  when `isSupported()` is false — both rejected in design.
- The capability probe (dead-end unchanged — a device that fails
  isSupported never reaches it; do not add a direct-floor fallback
  there, it recreates the silent-TV behavior).

## Handoff

- The beacon detail must stay INV4-clean (no play URL, no token) — the
  detail is the layout string, nothing else.
- The refusal must not swallow the capability probe's concerns: the two
  dead-ends are disjoint (probe = MSE present, codecs unprobed; refusal
  = MSE absent, rendition layout).
