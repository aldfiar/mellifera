# 3.1 Lazy repack-on-play for legacy-layout builds — one enqueue per stale build

## Goal

The silent titles heal themselves on the next watch attempt: a complete
build whose layout predates the composed master repacks lazily when the
item is played — exactly one enqueue per stale build, the old build
serving until the fresh nonce replaces it — instead of staying silent
forever behind a healthy-validating legacy layout that no sweep, no
frontier pass, and no retry will ever touch.

## Done when

- The streams lane's success persist writes `master: true` into the
  namespace's streams doc; a failure persist writes no marker; a
  hand-seeded legacy doc answers marker-absent.
- The play verb (`!retry`) on state `complete` + build nonce + no marker
  enqueues exactly one repack, logs "orchestrator: legacy repack queued"
  (item only — INV4), and answers per pack-on-play; concurrent plays
  while the repack is pending/running enqueue nothing (lease-absorbed);
  a marker-carrying build never re-enqueues.
- A gate-closed stale item (knob-off HEVC) logs ONE "orchestrator:
  legacy repack skipped" INFO line (item + refusal token), keeps
  answering its existing build, and takes on no state change and no
  ledger row.
- Both new lines hold INV4 (item id and refusal token only — never a
  token value, never a play URL).

## Audit

Not an audit task.

## Out of scope

- Any library-wide sweep wave or boot-time requeue of legacy builds.
- Any read-side rewrite of published playlist bytes (D5's declined
  alternative).
- The descriptor and its decision line (task 4.2); the publish and
  job-start flow lines (tasks 4.1/4.3).
- Changes to `EnqueuePack`'s channel semantics or the per-item lease —
  the absorb IS the existing behavior.
- The repack the verb enqueues is the ordinary lane job: its
  publish/fail lines and failure contract belong to the existing lane
  contract (design D5's Risks entry), not to this task.

## Handoff

- The stale-build decision reads ONLY the stored namespace doc — never
  the playlist on disk; if the doc shape makes the marker read awkward,
  widen the success doc, not the decision's inputs.
