# 1.1 Rendition master composition — the lane composes the RFC 8216 master

## Goal

A rendition pack's build root serves a master playlist a compliant player
composes correctly: the video rendition as the only `EXT-X-STREAM-INF`
variant (with CODECS), the audio renditions ONLY as `EXT-X-MEDIA` group
members with unique NAMEs and exactly one `DEFAULT=YES`. ffmpeg's
double-listed master (every rendition also listed as a variant, all audio
entries `DEFAULT=YES` — finding A: hls.js picks the video-only variant and
never requests any audio rendition) never survives to a published build.

## Context pointers

- design: design.md D1 (the composed master's shape and attribute
  provenance), D2 (composed at the head-first publish from the head
  playlists — the probe moment moves), D6 (unexported; zero new exports),
  Open Question 1 (DEFAULT=YES on the embedded audio) and 2 (EXT-X-MEDIA
  CODECS optional — task judgment, carry-when-composed recommended)
- code: `internal/stream/pack.go` — `packInto` (`:142`, the heads are read
  into memory before either publish path — the composition moment),
  `publishHeadOnly` (`:183`, writes variant playlists into tmp before the
  rename — the master writes beside them, overwriting ffmpeg's head
  master), `renditionArgs`/`renditionMap` (`:297`/`:346`, the rendition
  order and the `aud` group id the master's EXT-X-MEDIA entries must
  mirror: rend0 video, rend1 embedded audio, rendK+1 voiceovers);
  `internal/stream/codecs.go` — `buildCodecs` (`:137`, the probe loop that
  reshapes to serve both the record and the master), `codecString` (the
  table, untouched here); `internal/stream/playlist.go` — `tokenizePlaylist`
  already rewrites plain URI lines and `URI="…"` attributes (master refs
  tokenize with zero change); ffmpeg's tail master landing under `t/` via
  `moveTree` is harmless (validated, unreferenced) — MAY be removed
- specs: packaged-playback delta "Master playlist on every pack" —
  scenarios "Rendition pack serves a video-only variant master with an
  audio group" and "Uncomposable codecs keep the corrected master shape"

## Done when

- `go test ./internal/stream -run TestPackRenditions` passes: a real
  rendition pack's build root playlist carries exactly one
  `EXT-X-STREAM-INF` variant with a CODECS attribute, the audio renditions
  as `EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="aud"` entries with unique NAMEs,
  exactly one `DEFAULT=YES` (embedded audio), voiceovers
  `AUTOSELECT=YES,DEFAULT=NO`, and NO audio rendition as a variant.
- A new table/shape test (`TestMasterPlaylist`) pins: byte-identity of the
  composed master for identical facts; the attribute-less degradation when
  the codec record composes nil; the tail merge leaving the master
  untouched (complete at birth); ffmpeg's master absent from the published
  root.
- `Build.Codecs` keeps its pinned order (video, embedded audio, then
  voiceovers, deduped) — `TestPackCodecs` stays green.

## Audit

Not an audit task.

## Out of scope

- The single-variant layout move and its master (task 1.2).
- The itest assertions observing the layout (tasks 1.3/3.1).
- Any serve-side or validate-side code change (both are layout-agnostic;
  only tests pin them).

## Handoff

- If ffprobe of a head EVENT playlist proves flaky for some fixture, the
  fail-open rule wins: attribute-less master, nil record, pack still lands
  — never a pack failure, never a guessed CODECS attribute.
