# 6.1 On-device parity walk evidence (OPERATOR-ASSISTED)

## Goal

Walk the deployed app on the REAL TV box (192.168.0.215, adb through the
`.claude/skills/adb-local` python relay — the box cycles off the network every
few minutes, so the walk is ONE batched script with `|| true` continuation)
and record each parity surface's evidence under a `WALK-RESULT:` heading in
this file. The mechanical duty cannot prove device results — `audit: true`
makes the reviewer READ this file at GATE 2; the duty only greps the marker.

## Context pointers

- relay recipe: .claude/skills/adb-local/SKILL.md (relay_serve.py + adb
  connect 127.0.0.1:15002; canonical adb at ~/Library/Android/sdk/platform-tools)
- 2026-11-12 audit precedent: .tmp/tv-ui-backup-2026-11-12/ — screenshots +
  uiautomator dumps + logcat tails; the same artifact set is this walk's
  output shape
- design: design.md D10 (evidence law), D4/D5/D6 (the surfaces walked)
- spec: android-tv-client delta — the scenarios this walk exercises

## Done when

This file carries `WALK-RESULT:` sections for each surface, each with the
screenshot path, the uiautomator text dump assertion (blocks present / honestly
absent), and an explicit pass/fail call:

- WALK-RESULT: visibility — titles/meta/loading rows legible on every walked
  screen (the 2026-11-12 black-on-black defect class)
- WALK-RESULT: card law — ✓ glyph at meta scale on watched cards, NO word
  chips; progress bars where progress exists
- WALK-RESULT: home rows — Continue resumes from stored position; Next-up OK
  plays; empty history renders no row; LEFT at row-0 x=0 opens the rail
- WALK-RESULT: series detail — hero + Synopsis (or honest absence); episode OK
  starts playback (the fixed dead-OK)
- WALK-RESULT: collection bodies — image chips filter + counts match; unknown
  module renders label + empty
- WALK-RESULT: watch flow — controls reveal info blocks; skip chip in range;
  auto-next card on end

## Audit

This IS the audit payload — the reviewer reads the WALK-RESULT sections at
GATE 2 and checks they are real device observations (real screenshots, real
a11y dumps), not projections. An unwalked surface recorded as walked is the
failure mode this guard exists for.

## Out of scope

- Fixing anything the walk falsifies: a FAIL opens an amendment round (propose
  re-entry), never a silent workaround inside 6.1.
- Performance/decode probing — the android-tv-app T0 evidence already covers
  the playback machinery; this walk proves LAYOUT parity only.

## Handoff

- GATE 2 reads this file as the on-device leg of every parity requirement.
- Future web-UI changes that touch a walked surface get a fresh walk entry
  under this capability (the drift check), never a silent skip.

## WALK-RESULT: playback VIDEO — TWO DEFECTS ROOT-CAUSED (operator's report)

The operator watched: audio plays, screen stays black. Confirmed and split
into two independent defects:

1. **Punch-through (5.3 — FIXED in-tree, green; 0.3.1 APK built+installed).**
   `PlayerOverlayShell` wrapped the player in Compose `Surface`, whose opaque
   material background fills the window; the SurfaceView's video composites
   BEHIND the window, so the cover hid it entirely. Introduced by the base
   change's 5.9; no prior on-device walk had looked at the picture. Fix: the
   shell is a plain transparent Box (design D7 punch-through law).
2. **Surface lifecycle (5.4 — FIXED + compositor-proven on 0.3.2).** Even with the cover gone,
   frames never reached the surface: the AndroidView update-block attached
   `holder.surface` at composition time — null before surfaceCreated — and
   nothing re-attached; `setVideoSurface(null)` = Media3 dummy mode.
   On-device proof of the DEFECT (0.3.1): vendor MediaCodec log
   `[ROB]V id:N … r:0, drop frame` at ~24/s with full-rate input (QIB 24/s —
   decode-and-discard), while SurfaceFlinger shows `SurfaceView[tv.mellifera/...]`
   layers alive with `buffer=0x0` / `composition type=INVALID` and the
   Background layer painting full-screen opaque black (walkP P04-sf-*, P05-sf-full.txt).
