# 1.2 Generalized rendition composition + the DEFAULT-audio rule

## Goal

The rendition composition drives N embedded audio streams — one
`-map 0:a:i` per stream, one audio rendition each — and the composed
master puts its single `DEFAULT=YES` on the most compatible track (the
first AAC in rendition order, ties → source order). The 1-embedded flags
pin stays byte-identical; the pin table extends with the embedded=2 case.

## Done when

- The flag pin stays green unchanged for its existing case and the new
  embedded=2 case pins: `-map 0:a:0`, `-map 0:a:1`, the sidecar maps,
  and the var_stream_map with embedded+sidecar audio entries in output
  order — remux-only (the banned-encoder assertions keep running).
- Master unit cases: flac-first + aac → DEFAULT on the aac rendition;
  two aac → DEFAULT on the first (source order); no AAC → DEFAULT on the
  first rendition; unprobed variants skipped in preference; always
  exactly one DEFAULT=YES.
- `TestPackMultiAudioRenditionLayout` stays green (the end-to-end
  composition), `TestPackRenditions` stays green (the voiceover order
  and soft-omit behavior unchanged).

## Out of scope

## Handoff

- var_stream_map audio indices are OUTPUT stream indices in map order —
  get that wrong and ffmpeg splits variants in the wrong order; the
  repro's rend1/rend2 codec assertions will catch it.
- The DEFAULT rule reads the probed variant facts (codec_name); a
  variant whose probe failed composes no codec facts — skip it in the
  preference, never fail the pack.
