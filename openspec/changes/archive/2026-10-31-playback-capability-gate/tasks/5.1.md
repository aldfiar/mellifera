# 5.1 Joint itest — codecs wire, publish replacement, retry refusal

## Goal

The three cross-group contracts of this change hold over REAL instances,
no mocks: the recorded codecs survive to the served descriptor, publish
replaces the item's builds, and the gate refusal rides the real router.

## Context pointers

- design: design.md §Interfaces (the descriptor `codecs` shape and order;
  the play-refusal 400; the AfterPackPersist ordering), D2 (recorded vs
  legacy composition), D5 (eviction after the doc write)
- code: `internal/itest` — the joint harness style (`TestPlaybackRoundTrip`
  boots the real router + Deps wiring and packs through the real lane with
  generated fixtures; `TestBrokenBuildRepackSweep` is the repack-drive
  precedent); ffprobe of the published init segment inside the test is the
  codecs oracle (the same check task 2.1 pins, now over the served wire)
- wire: (a) `GET /api/v1/items/{id}/playback` on a freshly packed item →
  `mode:"hls"`, `codecs:[avc1…, mp4a.40.2…]` matching the init segment's
  sample entries; (b) after repacking the same item → exactly one build
  directory under `data/streams/<id>/`, the descriptor answers the new
  nonce; (c) `POST /api/v1/items/{id}/play {retry:true}` on a seeded
  gate-closed failed item (opt_in facts + knob off) → 400 body whose error
  code is `codec_not_opted_in`
- specs: packaged-playback delta scenarios "Packaged descriptor carries the
  pack's codecs", "Fresh build replaces the item's previous builds",
  "Retry refused by the gate answers the descriptor's own token" — this
  task is their Tier-1 joint realization

## Done when

- `go test ./internal/itest -run TestPlaybackCapabilityGateJoint` passes
  with all three joints asserted against SERVED bytes (parse the response
  bodies — the json tags are the contract, not the Go structs).
- The eviction joint asserts the ON-DISK state (directory listing), not a
  log line — one build directory remains and it is the nonce the
  descriptor answers.
- The refusal joint asserts the token equals the descriptor's
  `state_reason` token for the same seeded item — the agreement scenario
  is the point.

covering test; the reviewer re-runs the duty and checks the qa list
reality. The REAL covering test nodes (no `tests/` tree in this repo, no
dedicated refusal file): the joint test
`internal/itest/playback_capability_gate_joint_test.go`
(`TestPlaybackCapabilityGateJoint`, all three legs) and
`TestPlayGateRefusal` inside `internal/api/playback_test.go` (the 400
handler mapping). The registered `qa:` entries keep the register
grammar's `tests/...::node` shape and spell these same nodes.
