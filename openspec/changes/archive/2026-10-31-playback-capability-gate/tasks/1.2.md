# 1.2 Enqueue-site gates — retry refusal + repack refusal

## Goal

The two un-gated ENQUEUE seams stop enqueuing what the pack gate refuses,
each with its own honest surface: the play verb's retry answers the gate
token over the wire; the integrity repack sweep refuses in the log.

## Context pointers

- design: design.md D1 (the PackGate judge — this task only consumes it,
  1.1 owns it), D4 (refusal-is-not-a-failure), Interfaces (the PlayRefusal
  error shape)
- code: the retry branch `cmd/mellifera/main.go:317-342` (`state == failed`
  → `EnqueuePack`, no classification — the hole this task closes); the
  integrity repack enqueue `cmd/mellifera/playback.go:288-294`; the api
  play handler `internal/api/playback.go` (`itemPlay` — `nothing_failed`
  is the 400 family precedent, `sql.ErrNoRows` the typed-error mapping
  precedent); api gains the exported `PlayRefusal` error type (Interfaces)
- wire: `POST /items/{id}/play {retry:true}` on a gate-closed failed item →
  `400 {error:{code:"codec_not_opted_in"|"codec_unsupported", ...,
  retryable:false}}`; the SPA renders canonical errors inline already —
  no SPA change in this task
- specs: packaged-playback delta "Opt-in gate on the pack lane" —
  scenarios "Retry refused by the gate answers the descriptor's own token"
  and "Repack sweep refuses without enqueue or ledger row"

## Done when

- `go test ./cmd/mellifera -run TestPlayRetryGate` passes: a seeded failed
  opt_in item with the knob off refuses retry (no enqueue observed via a
  stub enqueue func, PlayRefusal carries the token); the same item with the
  knob on re-enqueues and answers 202-shaped `(true, nil)`; a gate-open
  failed item behaves byte-identically to today.
- `go test ./internal/api -run TestPlayGateRefusal` passes: the handler
  maps PlayRefusal to 400 with `code = Reason` and `retryable: false`
  (parsed from the response body), and `nothing_failed` still answers for
  the no-failed-run case.
- The repack sweep path is covered by the cmd test's sweep-side case (or a
  sibling test in the same file): a gate-closed unhealthy item emits one
  INFO refusal line and no enqueue call; healthy and gate-open items
  enqueue as before.
