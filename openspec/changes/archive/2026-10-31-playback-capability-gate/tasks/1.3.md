# 1.3 Build-time gate — policy refusal without ledger poisoning

## Goal

A pack job that reaches the build executor after the knob flipped (enqueue
judged, build refuses) ends as an honest `failed` state with NO
`pack_failed` ledger row — a knob setting never charges the flat 30-day
cooldown, and re-enabling the knob heals through the frontier with no
manual step.

## Context pointers

- design: design.md D4 (the enrich PolicyRefusal branch and why the ledger
  must stay out of it — the F1 poison class is the failure being prevented),
  Interfaces (PolicyRefusal shape)
- code: the PackItem seam `cmd/mellifera/main.go:215-218` (the closure
  where the gate check wraps `mediaSvc.Pack`); the streams lane driver
  `internal/enrich/streams.go:95-109` (`workStreams` — today ANY packErr
  takes `recordPackFailure` + `failedStreamsDoc`; the refusal branch
  splits BEFORE `recordPackFailure` and persists the failed state with the
  policy reason); `failedStreamsDoc` (`streams.go:180-186`) is the failed
  shape to reuse (state/failed_at/reason — reason carries the token)
- wire: no HTTP surface; the persisted `doc["streams"]` gains
  `{state: "failed", reason: "codec_not_opted_in"}` (the existing free-
  text reason field — not the read-side `state_reason` projection); the
  ledger gains nothing
- specs: packaged-playback delta "Opt-in gate on the pack lane" —
  scenario "Build-time refusal fails without poisoning the ledger"

## Done when

- `go test ./internal/enrich -run TestPackPolicyRefusal` passes: a PackItem
  stub returning PolicyRefusal leaves NO row via the failure ledger store,
  persists `state: failed` with the token in `reason`, and a knob-on retry
  through the frontier's eligibility (no CoolUntil) re-enqueues.
- `go test ./internal/enrich -run TestStreamsLane` stays green: real pack
  failures (non-refusal errors) still record the ledger row exactly as
  today; the success path is untouched.
- The cmd PackItem closure's gate check is covered by 1.2's cmd tests or a
  sibling case in the same file: the closure returns PolicyRefusal when
  PackGate refuses and never calls Pack.

## Audit

Not an audit task. The exported-surface addition (one error type) is
reviewed at the gate per design.md Risks.

## Out of scope

- Cooldown classification (infra-vs-content) — the named postmortem
  follow-up; this task only keeps POLICY refusals out of the ledger.
- The enqueue-site gates (task 1.2) and the predicate (task 1.1).

## Handoff

- The refusal's `reason` string and `state_reason`/error-code tokens are
  the same constants (design D1) — if a test sees a different spelling,
  the constants drifted; fix at the source.
