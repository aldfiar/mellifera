# Contract — task 5.1 (search rides the relay)

## Task

- **Id / Title:** 5.1 — Network-class search failures enqueue purpose=search jobs and the search closure polls ≤60 s before answering; non-network failures unchanged. @qa
- **Duty:** `go test ./internal/enrich -run TestSearchRelay -count=1 || exit 1`
- **Downstream:** none — the api search endpoint and closure signature are untouched; the SPA picker and the relay loop (6.x) meet inside this behavior.

## Scope

**In:**
- `internal/enrich/search.go` (the SearchSource fetch branch: enqueue + poll)
- `internal/enrich/search_test.go` (new table-driven cases)

**Out:** `internal/api/identify.go` and the search endpoint's wire contract (byte-identical), `relay.go` (2.x methods are called, never edited), the enrichment chain (group 3).

## Design pins

- The poll lives INSIDE the closure (D8): the endpoint holds the request because its closure holds it — no job-id handback, no SPA completion handshake, no endpoint change.
- Budget: ≤60 s, a named constant — no env knob for a UX budget (design.md D8); the poll checks job state (done → SearchResults over the stored response; failed/expired → the existing upstream-error answer with retry disabled).
- Search jobs carry `purpose: "search"` and NO ledger row; their give-up is the budget, not the three-round rule.
- A non-network search failure (upstream/protocol/spec, or search unsupported) keeps today's immediate answer — the relay is the network-class path only.

## Acceptance

- The duty exits 0: the search-relay tables green.
- Tests assert: a relayed search completing within budget answers the candidates; an unclaimed job expiring the budget answers the upstream error; a non-network failure answers exactly as before the change.

## Constraints

- SearchSource's signature and the api closure's shape stay byte-identical — the identify picker and the endpoint compile untouched.
- The poll must remain cancellable by the request context (an operator closing the picker aborts the wait cleanly).

## Handoff

- The relay loop (6.2) executes search jobs concurrently with this wait — the joint's not tested here (the budget timeout is), but the reviewer may pair 5.1's green with 7.1's transport joint at the gate.
