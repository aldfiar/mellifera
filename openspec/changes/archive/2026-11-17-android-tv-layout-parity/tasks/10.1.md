# 10.1 Serial facet lane contract (audit P1-3)

## Goal

The serial grid gains the SPA's facet lane: served facets from
/libraries/{id}/facets, one conjunct value per key driving the /series
query, rendered in EVERY body state. Covers the wire + flow (task 10.1) and
the lane UI (task 10.2, same contract).

## Wire law

- GET /libraries/{id}/facets → {facets: [{key, values: [{value, count}]}]};
  facets is always non-nil
- /series accepts ?genre&kind&status (query params only when non-null); an
  unknown value returns the server's honest empty list
- Dtos mirror (L6): FacetValueDto(value, count), FacetDto(key, values),
  FacetsResponse(facets); PARAM_OF: genres→genre, kind→kind, status→status

## Flow law

- BrowseState gains facets: List<FacetDto> + facetSelection:
  Map<String,String> keyed genre/kind/status
- ONE conjunct value per key, AND across keys
- toggle: the active value again → clear that key; a different value → set
  it; every change refetches the serial grid with the current params (the
  pickFolder commit/restart idiom minus revert — a facet toggle is
  immediate)
- the facets fetch is best-effort: a failure leaves facets empty (no chips)
  and never kills the grid

## Lane law (task 10.2)

- the lane renders in EVERY serial body state — loading, error, empty,
  grid — above the body content
- reuse the FolderChipsRow shell: the shared chipFocus cursor, the
  chipsRowConsumesUp clamp, the BackHandler ordering; the active value in
  the accent (the FolderChip active law); values verbatim with their counts
- undefined facets render no chips; the lane shell still owns its row (the
  lane is the control, not a data block)
