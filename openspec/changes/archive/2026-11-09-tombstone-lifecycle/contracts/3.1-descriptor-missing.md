# Task 3.1 - Descriptor file-missing state

## Task

- **Id**: 3.1
- **Title**: `StateMissing`/`ReasonFileMissing` consts + the composition-root stat gate
- **Duty**: `grep -q 'StateMissing' internal/stream/describe.go && grep -q 'ReasonFileMissing' internal/stream/describe.go && go test ./cmd/mellifera -run 'TestDescriptorFileMissing|TestPlaybackDecisionReason' -count=1 || exit 1`
- **Downstream**: 4.1 (web union + banner), 5.1 (openapi/embedded regen); the packaged-playback delta's MODIFIED descriptor requirement.

## Scope

In:

- `internal/stream/describe.go` — read-side projection consts `StateMissing = "missing"` and `ReasonFileMissing = "file_missing"` beside the existing honesty states/reasons. `Describe` itself UNCHANGED (pure over the doc; no fs access).
- `cmd/mellifera` — `playbackDescriptor`: after Describe answers, when the answer is the DIRECT floor (the play URL is the original), `os.Stat` the resolved original (the `parsed.absolute_path` stamp — the same channel `originalResolver` reads); stat-miss → state `missing`, reason `file_missing`, play URL emptied. hls answers never stat. The decision log renders state/reason through the existing fields.
- Tests in `cmd/mellifera`: `TestDescriptorFileMissing` (missing file → missing/file_missing with no playable address; present file → today's answer byte-identical; hls answer → no stat performed). The existing `TestPlaybackDecisionReason` stays green.

Out:

- `Describe`'s logic and its fs-free purity; the pack lane; `codecs_src=none` (seeded follow-up, NOT here); the `/media` 404 backstop; web (4.1); any stored-state write.

## Design pins

- The stat lives at the composition root, not inside Describe: Describe is pure over the document (its contract and test suite rely on that) and the original channel is resolved in cmd.
- Direct answers only: an hls build is the playable truth (`ValidateBuild` guards its integrity); stat-checking a stale source would retire a playable pack.
- `missing` is a read-side projection — never stored in the packaging namespace (the `preparing`/`unsupported` law).
- Wire additive: new state value + new reason value; the `Playback` struct shape is unchanged (State/StateReason are plain strings); the play URL empties on the missing answer rather than pointing at a 404.
- The stat must reuse `originalResolver`'s channel — never a second path derivation.

## Acceptance

- Missing file → mode `direct`, state `missing`, reason `file_missing`, no playable address; the decision log names it.
- Present-file and hls answers stay byte-identical to today.
- The named cmd tests pass.

## Constraints

- No stored-state writes, no packaging namespace changes, no schema.
- No re-probe, no ffprobe — a single stat.

## Handoff

- 4.1 consumes the wire values; 5.1 regenerates the contract.
- audit: true — the GATE reviewer reads this file.
