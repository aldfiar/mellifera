## Scope

- New tests in `internal/scan`: `TestItemSweepTombsVanishedFiles`, `TestItemSweepSkipsPresentFiles`, `TestItemSweepSkipsAbsentStamp`, `TestTruncatedStreamSkipsItemSweep`, `TestReobservedDeletedItemSelfHeals`.

## Design pins

- Location is run.go beside sweepSeries, not a new package — the sweep shares the series sweep's gate so a truncated stream never sweeps (the existing truncated-stream tests stay green).
- Disk truth, not observation set: the stat decides. A present file never tombstones; an absent one tombstones regardless of which pass last observed it.
- The status literal is `scanStatusDeleted` ("deleted") — the enrich-owned lifecycle vocabulary (`internal/enrich/state.go`, INV-status-owner). Never a new literal.
- The heal leg mirrors the series self-heal: without it, `nextScanState`'s prior-status preservation keeps a restored file dead forever, and the offline-root mass tombstone (design R1) would be permanent.
- The sweep is silent on success; warnings ride scan.Result like every soft-fail.

## Acceptance

- A clean rescan over a library with one vanished file tombstones exactly that item — doc bytes unchanged, progress/ledger rows intact.
- A truncated stream sweeps nothing; a cancelled context aborts the sweep.
- An absent-stamp item skips with a warning and keeps its status.
- A re-observed deleted item heals to `ready` (unchanged identity) or `stale` (changed).
- The five named tests pass; the pre-existing scan suite stays green (the full suite re-runs at the gate).

## Constraints

- No schema migration, no new tables — the status column only.
- Present files' status path through `nextScanState` is byte-identical to today.
- The sweep stays O(active items) — one stat per item, no re-walk of the tree.
