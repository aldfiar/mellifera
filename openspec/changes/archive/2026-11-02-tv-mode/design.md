# Design

## Context

The SPA is a single React + Vite tree (`web/src/`) embedded into the Go binary via `make web-build`; display-wide state rides classes on the root elements with localStorage persistence under fixed `mellifera.*` keys — the shipped precedents are `mellifera.theme` (`dark` class on `<html>`, module-eval boot apply, `ThemeToggle.tsx`) and `mellifera.side` (`side-open` class on `<body>`, `Sidebar.tsx`). Keyboard transport is already centralized: `web/src/lib/playerShortcuts.ts` is the pure key→action table of the 3.4 keyboard, and its module doc names this change ("Layer 7 (TV mode) will normalize remote media keys onto the SAME table — this module is the single normalization point, so transport behavior cannot fork per input device"). Overlay mechanics are equally centralized: `DialogShell.tsx` owns portal, scrim, Esc forwarding (the consumer's `onEscape` policy wins when present), the focus trap, and focus-return — every overlay consumer shares it, so one mechanics change gives every overlay Back for free. Density is contract-tested: `lib/density.ts` emits the height-aware CSS strings, `density.test.ts` and `overlayContract.test.ts` pin `index.css` text via `readFileSync` (the fs-contract idiom — jsdom evaluates no media queries, so CSS is pinned by text and accepted visually by inspection, the `cardact-trigger` MANUAL TEST NOTE precedent). The item page already owns the photo-stage keys on desktop (`ItemDetail.tsx`: ←/→ step, S toggles slideshow, Esc stops-then-navigates) and the ONE watch-view keydown listener that calls `applyShortcut`. Baseline: 35 Vitest files / 450 tests GREEN; the wf index is CURRENT at f03a3f3 but maps the Go tree only — all web citations here come from direct file reads.

## Goals / Non-Goals

**Goals:**

- One `.tv` class, one CSS block, one pure resolver module: tv mode is a display mode of the existing SPA, not a second app.
- ALL transport and navigation keys resolve through mechanisms that already exist: the 3.4 normalization table (media keys) and the DialogShell close policy (Back) — zero new key-handling paths beyond the one walker.
- Honest degradation: an unrecognized device gets the desktop layout and a reachable override; nothing on any surface crashes when storage or user-agent-data APIs are missing.
- Desktop stays byte-for-byte: the tv block is inert without the class, and every shared module changed here keeps its desktop behavior identical.

**Non-Goals:**

- Pairing/QR login — deferred, needs a backend slice; the token form stays the login path.
- Audio feedback on focus moves — ruled out (see D7).
- New backend endpoints, Go source edits, API or schema changes — the slice is SPA + rebuilt dist only.
- TV-specific layouts for admin surfaces beyond what the shared shell/scaling rules already give them (they inherit the `.tv` scaling like every page).
- Supporting Chromium below the stated build floor (D8) — old boxes that cannot boot the Vite build are out of scope, not degraded-to.

## Decisions

**D1 — The `.tv` class and its writer follow the `mellifera.theme` idiom.** A new pure module `web/src/lib/tvmode.ts` owns: the fixed key `TV_KEY = "mellifera.tv"` (INV-fixed-key, values `"auto" | "on" | "off"`, invalid/absent → auto), the guarded localStorage read/write (private-mode/quota-safe, the `ThemeToggle`/`lib/auth.ts` posture), the ladder, `resolveTvMode`, and a module-eval boot side effect that toggles `tv` on `document.documentElement` — imported in `main.tsx` before `App`, so the class lands before first themed paint, exactly like `ThemeToggle.tsx`'s boot apply which colors even never-toggle surfaces (`/login`). Alternative rejected: an inline boot script in `index.html` — earlier paint, but untestable in Vitest and a second boot path; the ThemeToggle precedent already proves module-eval timing is sufficient.

**D2 — Ladder semantics: strong markers decisive; the bare "TV" token weak; corroboration never sufficient alone.** The draft's step 3 ("corroboration, never sufficient alone") needs concrete meaning or it is dead code. Settled: the ladder input is `{model?, userAgent, innerWidth, innerHeight, maxTouchPoints}`; STRONG markers (`SmartTV`, `BRAVIA`, `AFT\d`, `KFT`, `Silk`, `Leanback`, or a model-hint match) detect TV decisively; the WEAK generic `TV` token detects TV only when corroboration (≥16:9 aspect AND `innerHeight ≤ 600` CSS px AND `maxTouchPoints === 0`) also holds; corroboration alone (no marker at all) stays desktop. The async `getHighEntropyValues(["model"])` probe is an UPGRADE-only pass: when the synchronous ladder said desktop, a resolving model hint may add the class; it never removes it — no flicker fights with the sync decision, and the override (D9) still beats everything. Alternative rejected: awaiting the async probe before first paint — the class would land late and flash; upgrade-only keeps first paint synchronous and honest.

**D3 — The 4K-at-dpr-1 rule is absolute: vw/vh clamps only.** Every tv-mode size is a viewport-derived clamp (type `clamp(16px, 1.05vw, 30px)` on the root, rows as fractions of 100vh, content ≤ 92vw, overscan padding 2.5vw / 2.5vh — the settled value; the draft's ~2.5% made physical: padding rides the viewport so the same fraction is cut-proof on every shape). Scale by the REPORTED CSS viewport, never by device-resolution claims — the same panel reports 960×540 at dpr 2 and 3840×2160 at dpr 1, and a fixed-px tv theme is physically quarter-size on the latter. The rows-fit-100vh leg builds on the shipped density contract (`SERIES_GRID_TWO_ROW_MIN_VH`, `posterCardMaxWidth`, `posterTrackColumns` — the tv block derives its track budget from the same height fractions and collapses the collection header to one line), never re-does it. `tvCssContract.test.ts` pins the block's text (the fs-contract idiom) so a fixed px cannot drift in.

**D4 — Media keys normalize INSIDE the one table.** `playerShortcuts.ts` grows the media-key rows mapping onto the canonical 3.4 actions: `MediaPlayPause` → `togglePlay`, `MediaTrackNext` → `nextEpisode`, `MediaPrevTrack` → `prevEpisode`, `MediaFastForward` → `seekBy(+SEEK_STEP_SECONDS)`, `MediaRewind` → `seekBy(-SEEK_STEP_SECONDS)`, `MediaStop` → the NEW `exitWatch()` action (added to `PlayerShortcutActions`; the watch view supplies the body — leave the watch view back to the item page). `applyShortcut` stays the single entry point, so transport cannot fork per input device (the module's own stated invariant). Alternative rejected: a separate TV key map — two tables invite exactly the fork the 3.4 design forbade.

**D5 — The grid walker is a pure core plus a thin harness, with an order-independent yield protocol.** `web/src/lib/focusWalker.ts` (NEW, pure): `nextIndex({count, current, cols, key})` — row-major ±1 / ±cols, edge-clamped, NO wrap-around (the mockup clamps; wrap disorients at 3 m). The harness `web/src/components/TvFocusRoot.tsx` (NEW): ONE window keydown listener, active only in tv mode, rendered after `<Routes>` in `App.tsx`; discovery scans the document for visible `a[href]`/`button` elements in DOM order (grids are row-major in DOM); the column count derives from the first row's geometry; Enter is never handled (native activation). The YIELD protocol is structural, not registration-order dependent (ItemDetail re-arms its listener per episode, so listener ordering cannot be the contract): the walker ignores a press when (a) the event target or the focused element sits inside any `[data-tv-yield]` subtree — ItemDetail marks its photo-browse/watch container — or (b) the target passes `isTextEntryTarget` (reused from `playerShortcuts.ts`), or (c) an `.overlay-backdrop` is mounted (overlays own their keys; the focus trap keeps focus). The `data-tv-yield` marker on ItemDetail's container is the one new attribute. Alternatives rejected: `event.defaultPrevented` chaining (breaks when ItemDetail's listener re-registers after TvFocusRoot) and a shared "arrows claimed" module flag (hidden cross-module mutable state).

**D6 — History-Back lives in DialogShell, unconditionally.** On open the shell pushes one history entry (`history.pushState` with a marker on the state); `popstate` runs the consumer's close policy — `onEscape` when present (the Esc matrix: view walks, pending-mutation guards), else `onClose` — so Back and Esc behave identically with zero consumer changes. Closing by any other path (Esc, scrim, completed action, route-change unmount) consumes the pushed entry via `history.back()` under a suppress flag so the popstate handler never re-fires the close; at the root of the history Back stays plain router-back (never trapped). The push is UNCONDITIONAL across display modes: one mechanics path, no mode branches in the shared shell; desktop gains the standard Back-closes-overlay behavior while its rendering stays untouched. Alternatives rejected: gating the push on tv mode (a second behavior fork in the ONE overlay shell, and the desktop Back-closes-overlay is what every web app does anyway).

**D7 — No audio feedback on focus moves.** Ruled out per the draft's lean: the focus expression is the locked accent color idiom, always visible in tv mode with a thicker ring; sound adds an autoplay-policy surface and zero information the ring doesn't already carry.

**D8 — Chromium floor: the Vite 5 default, unmodified.** `vite.config.ts` sets no `build.target`, so the build ships the Vite 5 `modules` default (≈ Chromium 87 / ES2020). The floor is stated as Chromium ≥ 87; older TV SoCs (2018-era, Chromium ≤ 86) cannot reliably boot the bundle and are out of support — no runtime crash-guard is promised below the floor. Within the floor the ladder degrades honestly: unknown box → desktop + reachable override (D2/D9); unavailable APIs (`userAgentData`, storage) → guarded fallbacks, never a crash. Widening the transpile target for legacy SoCs is explicitly not done — it would tax every bundle for an untestable population.

**D9 — The override control sits in the side-foot, beside the theme toggle.** `TvModeToggle.tsx` (NEW): the three-state segmented control «Авто / Вкл / Выкл» rendering next to `ThemeToggle` in the sidebar's pinned profile block (`side-foot`); it writes `mellifera.tv` and applies the class immediately (live switch, the single class-writer contract below). Reachability on a TV: the menu FAB is a fixed focusable button, the walker reaches it, the panel opens, the foot is pinned. Alternative rejected: an admin-page-only setting — on a TV the operator is nowhere near an admin surface at setup time, and the theme toggle already established the foot as the display-preferences home.

## Interfaces (cross-group)

- **I1 — `<html class="tv">` (the mode contract).** Writers: the `tvmode.ts` boot apply (first load) and `TvModeToggle` (live switch) — the class is toggled, never set by two divergent code paths; consumers: the `.tv` CSS block (inert without it) and `TvFocusRoot` (listener armed only under it). Group 1 owns the writer; groups 3, 5, 6 consume.
- **I2 — `mellifera.tv` (the storage contract).** Values `"auto" | "on" | "off"`; absent/invalid/unreadable → auto; guarded try/catch store posture identical to `mellifera.theme`. Written by group 6's control, read by group 1's resolver; the INV-fixed-key comment style is mandatory (drift = bug, the `THEME_KEY` precedent).
- **I3 — The key normalization contract (groups 2 ↔ 3).** `playerShortcuts.SHORTCUTS` remains the ONLY key→action table; the media-key rows land there (D4); `exitWatch()` joins `PlayerShortcutActions` and ItemDetail supplies its body. The walker NEVER handles media keys or Enter — arrows only — so the two key consumers are disjoint by construction.
- **I4 — The yield protocol (groups 3 ↔ 4 ↔ the stage).** The walker skips presses from inside `[data-tv-yield]` subtrees, text-entry targets, and mounted `.overlay-backdrop`s (D5). ItemDetail (group 5's stage task) adds the marker to its browse/watch container; DialogShell's backdrop class (group 4) is the overlay guard's selector — both names are pinned by tests on both sides.
- **I5 — The overlay history contract (group 4 → every overlay consumer).** DialogShell: open → one `pushState` marker entry; `popstate` → the consumer's close policy (onEscape-else-onClose, the Esc matrix); any other close → consume the entry under a suppress flag (D6). Consumers change nothing: their `onClose`/`onEscape`/`returnFocusRef` props keep their meaning.
- **I6 — The boot order (group 1 → main).** `main.tsx` imports `lib/tvmode` before `App`, so the mode class exists before any consumer mounts (the ThemeToggle module-eval precedent). TvFocusRoot mounts after `<Routes>`; activation is checked per-event under the `tv` class, not per-mount.

## Risks / Trade-offs

- [TV user agents are a zoo — false positives flip a desktop into tv mode] → strong-vs-weak marker split with corroboration (D2); the override always wins (D9); a wrong first-load default costs one visit to the foot control.
- [The unconditional history push changes desktop Back feel] → Back-closing an overlay is standard web behavior; Esc/scrim/focus-return are untouched; the DialogShell test pins push/pop/consume so the stack cannot leak entries.
- [jsdom cannot evaluate media queries or layout] → CSS is pinned by fs-contract text tests (the `density.test.ts` idiom); the walker's geometry-dependent bits (column measurement, visibility) are isolated behind inputs the pure core takes as arguments; visual gates carry MANUAL TEST NOTEs (the `cardact-trigger` precedent).
- [The walker double-handles an arrow the stage/player also handled] → the yield protocol is structural (`[data-tv-yield]`, text-entry, overlay guards), never listener-order dependent (D5); both sides pin it in tests.
- [4K-at-dpr-1 regresses to unreadable fixed px during later edits] → D3 is a hard rule and `tvCssContract.test.ts` fails on any bare px in the tv block's size properties.
- [Old TV boxes below Chromium 87 cannot boot the SPA at all] → stated floor (D8), documented in the proposal; within the floor degradation is honest; below it nothing is promised.
- [The dist rebuild task fails clean-tree checks because swag is missing] → the duty exports `PATH="$PATH:$(go env GOPATH)/bin"` inline (the shipped `fix-poster-legacy-placeholder-backfill` 3.2 precedent).

## Migration Plan

None required — the change is additive SPA behavior shipped through the normal `make web-build` embedded-dist rebuild. Rollback is redeploying the previous binary image: no data, schema, API, or stored-state migration exists; `mellifera.tv` written by an upgraded client is ignored harmlessly by a downgraded one (unknown key).

## Open Questions

None — the draft's open questions are settled in D3 (overscan = 2.5vw/2.5vh), D7 (no audio), D8 (Chromium 87 floor), and the proposal (pairing out of scope; the dpr-1 4K rule carried as absolute).
