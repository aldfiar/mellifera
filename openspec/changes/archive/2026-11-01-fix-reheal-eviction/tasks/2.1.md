# 2.1 Retention sweep pass — the grace window gets its reaper

## Goal

Superseded builds stop being retained-forever the moment 1.1 lands: the
periodic streams sweep gains a retention pass that reclaims a superseded
build directory once it is past the grace on BOTH anchors — the directory's
own age and the item document's last write — using the existing
move-aside eviction vocabulary and no new log lines.

## Done when

- `TestSweepRetention` exists in `cmd/mellifera/retention_test.go` and
  `go test ./cmd/mellifera -run 'TestSweepRetention' -count=1` is green
  (the duty's grep guard exists because `-run` matching nothing exits 0 —
  the guard is what makes the duty red before the test lands),
  covering: a just-superseded directory (old mtime, fresh
  `updated_at`) survives; a fresh directory over an old document
  (in-flight pack shape) survives; past grace on both anchors the
  directory is gone (moved aside, then deleted); the document-named build
  survives in every packaging state; fresh `.tmp-` staging survives; stale
  staging and stale `.trash` are reclaimed; an orphan item's directories
  are judged on mtime alone; an unreadable row's item is skipped
  entirely.
- `evictDir` is the only deletion mechanism; no `resetStreamsState` call
  (retention never touches the document-named build — nothing to
  unpublish).
- No new slog line: reclamation rides `evictDir`'s existing
  `orchestrator: evicted artifact directory` line.
- The sweep passes run in order frontier → retention → budget → integrity;
  `sweepBudget`'s cap-off early-return is byte-unchanged.

## Audit

This is the audit task for the eviction-semantics rework (a new deletion
path in the orchestrator). The reviewer reads this file at GATE 2: verify
the dual anchor is implemented exactly (both comparisons `>= grace`, the
row-missing case judged on mtime alone, the read-error case skipping
BEFORE any eviction decision), that the stale predicate excludes the
document-named build for EVERY packaging state, and that a retention
reclaim can never unpublish (no `resetStreamsState` on this path).

## Out of scope

- The budget pass's stale-first ordering (task 2.2).
- Any grace knob, env var, or config surface (locked constant — D2).
- The integrity sweep (it validates only the document-named build; no
  interaction with retention).

## Handoff

- The mtime anchor reads the directory entry's `Info().ModTime()` — a
  serving session does not refresh it (reads never touch mtime), so the
  anchor measures age since last write, which is what the rule wants.
- If the janitor's boot-run (`runBoot`) makes the first retention pass
  fire before the first tick, that is expected (same cadence semantics as
  the other tasks) — do not special-case it.
