# 1.2 Single-variant master — every fresh pack carries CODECS at the root

## Goal

A single-variant pack (the common case — no voiceovers) publishes the same
master shape as a rendition pack: the build root holds ONLY the composed
master whose one variant line carries `CODECS="<video>,<audio>"`, with the
media playlist, `init.mp4`, and segments under `rend0/`. Finding C dies at
the source: hls.js composes its SourceBuffers from the playlist's CODECS,
so an HEVC pack stops fatal-ing on capable devices.

## Done when

- A real single-variant pack publishes root `index.m3u8` = the composed
  master (one variant, `CODECS="<video>,<audio>"`), the media playlist at
  `rend0/index.m3u8`, `init.mp4` and segments under `rend0/`, tail segments
  under `t/rend0/` — and the complete build passes `ValidateBuild`.
- The head-only path (whole file within the head chunk) publishes the same
  shape atomically; the partial path serves the master with the growing
  `rend0` media playlist beneath it.
- A hand-laid legacy flat-root layout (media playlist at the build root)
  still validates and serves — the coexistence pin.
- The play URL minted for the build names `index.m3u8` and answers the
  master through the token-gated surface (served bytes tokenized).
