# 5.1 Joint itest — descriptor honesty wire + beacon wire

## Goal

The two cross-group contracts of this change hold over REAL instances, no
mocks: the stream.Describe honesty projection survives the api wire exactly
as the SPA consumes it, and the SPA's beacon payload posts through the real
router to the served log line.

## Context pointers

- design: design.md §Interfaces (the descriptor plumb and the beacon wire —
  the shapes under test); D1-D3 (descriptor), D7 (beacon)
- code: `internal/itest` — the existing joint harness style (real router +
  real Deps wiring; see `TestVideoItemPagesJointE2E` and
  `TestPlaybackRoundTrip` for the boot pattern); seed items DIRECTLY
  through the store — Describe reads stored facts only, so a document with
  `ffprobe.format_name: "matroska,webm"` + an h264/AAC stream shape and
  `streams.state: "none"` needs no ffmpeg and no scan
- wire: descriptor — `GET /api/v1/items/{id}/playback` answers
  `{mode:"direct", state:"preparing", state_reason:"non_native_container",
  play_url:"/media/<id>/original?token=…", sections:[], voiceovers:[]}`;
  beacon — `POST /api/v1/playback-events` body
  `{item_id, mode:"direct", phase:"video-error", code:"MEDIA_ERR_SRC_NOT_SUPPORTED",
  detail:"…"}` → 204; server log captured via slog's test handler
- specs: packaged-playback delta scenarios "Non-native container answers
  preparing with a reason" and "Beacon accepted and logged" are the
  acceptance scenarios; this task is their Tier-1 joint realization

## Done when

- `go test ./internal/itest -run TestPlaybackUnblockJoint` passes with both
  joints asserted:
  (a) the seeded matroska item's descriptor through the REAL api handler
  (Deps wired like main) carries state `preparing`, `state_reason`
  `non_native_container`, a non-empty token-carrying play_url, and empty
  sections/voiceovers — the exact shape the SPA's 4.2 branch keys on; a
  seeded native-container item in the same harness answers `none` with no
  `state_reason` (the byte-compat guard);
  (b) the exact SPA payload shape posts 204 through the real router with a
  client-role principal, and the captured log carries the five fields with
  detail truncated and no token material.
- The joint asserts the SPA-side contract from the SERVED bytes (json tags),
  not from internal/api structs alone — parse the response body.

- Hls-lane joint coverage (the existing TestPlaybackRoundTrip owns it).
