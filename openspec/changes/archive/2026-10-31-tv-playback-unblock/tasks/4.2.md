# 4.2 ItemDetail pack-on-play wiring

## Goal

The item page turns a `preparing` descriptor into a pack: one
`POST /play {retry:false}` per descriptor instance, an explicit Preparing
surface instead of a raw-original attach, a bounded poll that exits to hls /
failed / stall, and an honest unsupported banner — the silent spinner path
is unreachable.

## Context pointers

- design: design.md D6 (one POST, then poll, then honesty about stalling);
  the poll interval (~2 s) and window (~5 min) are SPA constants within the
  pinned ranges
- code: `web/src/pages/browse/ItemDetail.tsx` — the descriptor useQuery
  (queryKey `["playback", item.id]`) and the existing `playRetry`
  useMutation (`playItem(item.id, {retry:true})` — the pattern to mirror
  with `retry: 0` + invalidateQueries on success); `web/src/lib/api.ts` —
  `playItem(id, {retry:false})` already supported server-side
  (`cmd/mellifera/main.go` Play closure `!retry` branch → `packOnPlay`);
  `web/src/components/playback/Player.tsx` is mounted only via the page's
  `player` element — the preparing surface REPLACES that element
- specs: web-ui delta "Pack-on-play wiring" (all four scenarios are the
  acceptance set); packaged-playback delta "Playback descriptor and verb
  split" (the state contract this consumes)
- vitest: `web/src/pages/browse/ItemDetail.test.tsx` — existing descriptor/
  player/retry cases are the table to extend (mock the descriptor per state)

## Done when

- `cd web && npx vitest run src/pages/browse/ItemDetail.test.tsx` passes,
  with new cases: preparing+non_native_container fires exactly ONE
  `POST /play {retry:false}` per descriptor instance (a poll refetch does
  not re-fire — the mutation keys on the descriptor instance, e.g. the
  play_url/state identity); the media element is NOT mounted while
  preparing (the Preparing surface renders); a polled refetch answering
  hls mounts the ordinary player; a polled refetch answering failed hands
  to the existing retry affordance (no second auto-POST); the poll window
  exhausting renders the stall state and STOPS polling; unsupported
  renders the reason banner with no player and no polling; a canonical
  error from the POST renders inline without auto-retry.
- `tsc --noEmit` stays clean (the type grows in 4.1 — already landed by
  group order).
- The unsupported banner wording derives from state_reason
  (codec_not_opted_in / codec_unsupported), never a bare "failed".

## Audit

Not an audit task — nothing beyond the diff for the reviewer.

## Out of scope

- Player-internal error banners and beacon sends (task 4.3 — the stall
  beacon, though, is THIS page's edge and lands here or is delegated to
  4.3's beacon helper; keep one owner: the page owns the stall beacon).
- The descriptor type and the beacon sender implementation (task 4.1).
- Any server-side change (groups 1-3 are landed by group order).

## Handoff

- The player mount path is unchanged for hls/direct answers — only the
  preparing/unsupported branches are new; 4.3's banners must keep working
  under this flow (a preparing item never reaches the Player, so its
  direct-lane banner cannot fire until hls/direct mounts).
