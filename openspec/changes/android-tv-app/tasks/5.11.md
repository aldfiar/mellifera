# 5.11 Client debug telemetry (tracer + snapshot + sender + gate)

## Goal

The ONE instrumentation path (design D5): a debug-build-always /
release-build-opt-in telemetry stream — playback trace, capability snapshot,
bounded sender — ingested server-side by 3.2's `/debug-events`, gated
two-tier so a release build is silent until the admin flips the device flag.

## Context pointers

- design: D5 (two-tier gate, one path); D8 (PlayerController readout — the
  tracer hangs off the player, never AppState)
- specs: android-tv-client "Telemetry two-tier gate"; device-telemetry
  "Debug events ingest" (the receiving contract — 3.2)
- server facts: debug flag arrives via GET /profile (device kind, additive
  debug field — task 3.1); INV4 is the absolute law: NO query string, NO
  token in ANY emitted event, stripped CLIENT-SIDE before send
- T0 read: tasks/1.3.md T0-RESULT sections feed the snapshot's expectations
  (what the box can actually decode)

## Done when

- Gate: emit iff `BuildConfig.DEBUG || profile.debug`; the profile is
  REFETCHED on every foreground resume so an admin flip lands within one
  app-switch; beacons emitted before a profile lands are DROPPED (accepted:
  pairing precedes playback in practice).
- Tracer: AnalyticsListener timeline — load events (PATH ONLY after
  stripQuery), HTTP status, format, decoder backend actually used, audio
  track selected (verifies the k+1 mapping live), first-frame timestamp,
  dropped frames, bandwidth, structured `PlaybackException.errorCode`;
  bounded ≤64 events/session, detail truncated like the server beacon bound;
  emitted as kind=playback-trace (item_id, mode, phase="trace", code,
  detail).
- Capability snapshot: once per session at login — device model, Android
  version/API, app+Media3 versions, display, audio paths, MediaCodecList
  decoder table for video/hevc + video/avc (profiles/levels, hw/sw, secure,
  max res/fps) — answers "old box?" empirically per device forever; emitted
  as kind=capability-snapshot (the payload rides detail — not item-scoped,
  no item_id/mode/phase).
- Sender: Channel(16) worker; 429 → cooldown then drop-oldest (best-effort —
  telemetry never blocks playback). Emitted kinds are 3.2's closed set —
  playback-trace | capability-snapshot | fatal | video-error | stalled, each
  with its per-kind required fields (fatal|video-error|stalled mirror the
  beacon five-field shape: item_id, mode, phase = the kind, code, detail
  ≤256); `crash` is never emitted (reserved server-side, ACRA deferred).
- Non-streaming diagnostics (ship regardless): stable `Mellifera.*` logcat
  tags on release too; «Поделиться диагностикой» share button in settings
  (visible when the gate is on) composing snapshot + last trace + versions.
- Tests (the duty): TracerTest::timeline_events_path_only (INV4),
  CapabilitySnapshotTest::decoder_table_shape, TelemetryGateTest::
  release_silent_until_flip, TelemetryGateTest::profile_refetch_on_resume,
  SenderTest::bounded_session_64.

## Audit

Not an audit task — the gate tests are the floor; the reviewer re-runs them.

## Out of scope

- The server ingest route (3.2) and the admin flip (3.1/6.1); ACRA
  (OQ-B5 — route reserves kind:"crash"); per-device JSONL sink (OQ-B4);
  SPA debug parity (OQ-B6).

## Handoff

- 3.2's ingest is the receiving contract: field names, the closed kind set
  playback-trace|capability-snapshot|fatal|video-error|stalled, per-kind
  required fields, detail bound — drift here is a joint break 7.1's
  DebugEventsWireJointTest catches.
- 5.7/5.8 expose the AnalyticsListener hook points and the beacon channel
  this task consumes.
