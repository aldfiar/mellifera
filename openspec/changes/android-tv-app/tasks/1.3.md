# 1.3 T0 on-device probe evidence (OPERATOR-ASSISTED)

## Goal

Run the probe app (task 1.2) on the REAL TV box over adb and record the four
device-risk outcomes here, each under a `T0-RESULT:` heading. This is the
acceptance evidence for AC-10/AC-13/AC-14's device legs and the gate for
OQ-T1..T4. The mechanical duty cannot prove device results — `audit: true`
makes the reviewer READ this file at GATE 2; the duty only greps the marker.

## Context pointers

- probe app: android-tvprobe/ (task 1.2), `adb install -r` the debug APK
- design: design.md OQ-T1..T4; D1 (the PlaybackService fallback is
  pre-committed if T3 misses the bar — one-file change behind PlayerController)
- evidence predecessor: .tmp/android-tv-app-design.md §Why (the four classes)

## Done when

This file carries four `T0-RESULT:` sections, each with what ran (stream
URLs/paths kind-identical to real content: a real HEVC pack, a real MKV
original, a real translated multi-EXT-X-MAP playlist), what rendered, and an
explicit pass/fail call:

- T0-RESULT: HEVC hardware decode (AC-10/OQ-T1) — does the real box decode
  the packaged HEVC HLS with hardware decoder (check the on-screen decoder
  readout), or software/fails?
- T0-RESULT: translated multi-EXT-X-MAP (AC-13/OQ-T2) — does ExoPlayer
  expose the rendition audio tracks and does switching between them work?
- T0-RESULT: Home-press media-keys bar (AC-14/OQ-T3) — press Home, wait
  N=5 minutes, press a media key: does it still control playback? MISS ⇒
  OQ-T3's MediaSessionService fallback enters the spine as an amendment.
- T0-RESULT: Compose for TV viability (OQ-T4/D1) — does the box's Android
  version run the probe's minimal Compose-free surface cleanly enough that
  Compose-TV is the right UI stack (falsify BEFORE any UI work)?

## Audit

This IS the audit payload — the reviewer reads the four T0-RESULT sections
at GATE 2 and checks they are real device observations, not projections.
An unrun probe recorded as run is the failure mode this guard exists for.

## Out of scope

- Fixing anything the probes falsify: a MISS opens an amendment round
  (propose re-entry), never a silent workaround inside 1.3.
- The real app's behavior (tasks 5.x) — the probe answers device questions
  only.

## Handoff

- 5.1 (scaffold) reads T0-RESULT Compose viability before building UI.
- 5.10 (MediaSession) reads T0-RESULT media-keys bar to decide whether the
  PlaybackService fallback variant is in or out of its scope.
- OQ-T1/T2 outcomes are recorded expectations for 5.7/5.8 — a MISS there
  re-opens design (no silent degradation to a worse posture).
