# 7.1 Cross-module wire joints — server contract vs app client (JVM-only)

## Goal

Tier-1 joint coverage for the server↔app wire: the app's REAL net+flow code
(Api.kt + DTOs + pairing/playback/progress/debug-events flows — no fake
controller) against OkHttp MockWebServer fixtures that mirror the REAL
handlers' wire shapes. The shapes are pinned on the Go side (internal/itest
qa_pairing_joint_test.go posture + the swag contract); this task proves the
client side of the same joints within the JVM-only constraint. The on-device
e2e stays AC-16/T0 — this task covers what CAN run JVM-only.

  pairing — router.go:202-203, pairing/service.go:174-189 (single-use
  pickup), :233-235 (double-approve conflict); playback — playback.go:92-95

## Done when

- PairingWireJointTest::full_cycle_with_single_use — POST /pair fixture →
  wait pending → approve → wait returns the token ONCE → second wait shows
  the consumed state with NO token (service.go:174-189 mirrored); the
  approved-no-token fixture (server-restart shape, :180-185) drives the
  app's re-pair path.
- PlaybackWireJointTest::descriptor_play_degrade_relative_url — descriptor
  fixture (mode direct, relative play_url with ?token=) → POST play fixture
  200 {queued:false} → the app resolves the RELATIVE url against its base
  and launches (token rides the query, never logged).
- ProgressWireJointTest::put_shape_round_trip — PUT /progress/{item_id}
  body the app sends byte-matches the handler's accepted shape (field
  names, seconds type).
- DebugEventsWireJointTest::beacon_shape_and_inv4 — the app's emitted
  debug-event body matches 3.2's enumerated kind set (playback-trace |
  capability-snapshot | fatal | video-error | stalled — `crash` is reserved
  server-side and is NEVER a fixture value) with each kind's required
  fields, and carries NO query string (INV4 strip-before-send proven across
  the joint); a 429 fixture drives the cooldown/drop-oldest branch. Fixture
  authority: tasks.md task 3.2 + design.md D8 (per-kind required fields).
- All four run under `testDebugUnitTest --tests 'tv.mellifera.joint.*'`.

## Audit

Not an audit task — the four joint tests are the floor; the reviewer
re-runs them and spot-checks one fixture against its Go-side handler test.

## Out of scope

- Real-server joints (that is internal/itest's Go-side home); on-device
  playback (T0/AC-16); MediaSession backgrounded keys (manual T0 probe).

## Handoff

- Fixture drift vs a Go-side handler test is a REVIEW finding, not a silent
  fix: the Go test is the shape authority (the server is the contract
  owner).
- If a joint exposes a REAL contract bug, the fix lands in the owning task's
  code (server or app), never by bending a fixture.
