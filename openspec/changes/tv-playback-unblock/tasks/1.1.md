# 1.1 Descriptor honesty — preparing/unsupported + state_reason

## Goal

The playback descriptor tells the truth about a direct floor a browser
cannot decode: state `preparing` (a pack can land) or `unsupported`
(packaging cannot help) with an additive `state_reason`, projected from
stored ffprobe facts only, for non-native-container floors — play_url
retained, hls answers and native-container answers byte-unchanged.

## Context pointers

- design: design.md D1 (state vocabulary, not a parallel field), D2
  (play_url stays), D3 (stored facts only, cooldown-blind)
- code: `internal/stream/describe.go` — `Describe` (returns
  mode/state/playURL/sections/voiceovers today; add the reason as a 6th
  return value; the D5 integrity guard at `buildHealthy` is the precedent
  for read-side projections); `internal/stream/classification.go` —
  `Classify` (packability with the opt-in knob folded in; the container
  fact rides the ffprobe blob's `format_name`); state/mode constants join
  the existing const blocks (`StateNone`/`ModeDirect` et al) — new
  `StatePreparing`/`StateUnsupported` go there, keeping the exported count
  flat; `internal/api/playback.go` — `Playback` + `playbackResponse` gain
  `StateReason`/`state_reason` (json omitempty); `cmd/mellifera/main.go`
  Playback closure passes the 6th value through
- specs: `openspec/specs/packaged-playback/spec.md` "Playback descriptor
  and verb split" (MODIFIED delta in this change carries the full behavior)
- evidence: `.tmp/playback-evidence-2026-10-31.md` (the MKV descriptor that
  spun the TV)

## Done when

- `go test ./internal/stream -run TestDescribeHonesty` passes: table-driven
  cases — unpackaged MKV packable → `preparing` + `non_native_container`;
  unpackaged MKV with knob-off opt_in classification → `unsupported` +
  `codec_not_opted_in`, knob-on → `preparing`; direct_only → `unsupported` +
  `codec_unsupported`; unpackaged mp4 → `none`, no reason, playable URL;
  packaged/broken-build answers unchanged; the persisted doc is never
  written.
- `go test ./internal/api -run TestPlaybackVerbs` passes: the wire carries
  `state_reason` only on preparing/unsupported/failed-with-non-native-floor
  answers (omitempty), hls and native answers carry none; GET stays
  non-mutating; the retry/400/404 scenarios still hold.
- Native-container set: mp4/webm native; everything else (matroska/mkv,
  avi, mpegts, …) not — judged from `format_name` substrings, documented in
  the Describe comment.
