# 3.1 Playback-event beacon endpoint

## Goal

`POST /api/v1/playback-events` in the browse role group: a fire-and-forget,
rate-limited, shape-validated telemetry beacon whose entire effect is one
INFO log line — no store read, no persistence, no credential in the shape.

## Context pointers

- design: design.md D7 (a route, not a subsystem) + Interfaces (the beacon
  wire shape — the single home of the contract)
- code: `internal/api/router.go` — the browse role-group block
  (`r.Post("/items/{id}/play", h.itemPlay)` et al; add
  `r.Post("/playback-events", h.playbackEvent)` — top-level under /api/v1,
  NOT nested under /items); `internal/api/playback.go` — the canonical
  error body helpers (`writeError`, `errorBody`) and the swag annotation
  style (`@Summary/@Tags/@Router/@Param/@Success/@Failure`, `@ID`
  playback-event-beacon); `cmd/mellifera/httplog.go` — the request-log
  middleware this line correlates with; User-Agent via
  `r.UserAgent()`
- specs: packaged-playback delta "Playback event beacon" (the behavior);
  web-ui delta "SPA consumes only pre-existing endpoints" (the allowlist
  already lists the route — this task makes it real)
- roles: browse group gates admin+client (a pairing-minted client session
  — the TV — must reach it); `internal/api` stays free of any new import

## Done when

- `go test ./internal/api -run TestPlaybackEvents` passes, table-driven:
  well-formed beacon → 204 no body; malformed JSON / wrong enum
  (`mode` not direct|hls, `phase` not fatal|video-error|stalled) →
  canonical 400 `bad_request`; missing required fields → 400; the rate
  limit (per-client, in-process, small burst) trips to 429 `rate_limited`
  and logs NOTHING for the rejected ones; exactly one INFO line per
  accepted beacon carrying item_id/mode/phase/code/truncated-detail + UA
  (captured-log assertion); a client-role principal is accepted; no auth →
  401 via the standard middleware; unknown item_id accepted verbatim (no
  store read — assert with a nil Store in Deps if the handler can run
  without one).
- `detail` truncation is a named constant (bounded, e.g. 256 chars) and the
  truncation is asserted in the captured log.
- No token value can appear: the struct has no credential field, and the
  handler logs only its five fields + UA.
