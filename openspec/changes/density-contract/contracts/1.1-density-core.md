## Design pins
- The module exports EXACTLY four symbols: `posterCardMaxWidth`, `photoStageMaxH`, `SERIES_GRID_CHROME_PX`, `PHOTO_STAGE_CHROME_PX` (per-package bar is 8; leave headroom for the 7.2 TV mode's successor change).
- `posterCardMaxWidth({chromeH, rows, cardBodyH, minCardW})` returns `min(100%, max(<minCardW>px, calc((100vh - <chromeH + rows*cardBodyH>px) / <rows*3/2>)))` — `minCardW` optional, default 120; the emitted string contains `100vh` VERBATIM (no viewport numbers are read or baked in — the browser owns the viewport).
- `photoStageMaxH(chromeH)` returns `max(calc(100vh - <chromeH>px), 320px)` — the 320px floor is not configurable (one degenerate-case answer).
- The chrome constants carry the 2026-10-24 measurements with derivation comments: `SERIES_GRID_CHROME_PX = 302` (182px header + 2x60px card bodies), `PHOTO_STAGE_CHROME_PX = 136`. They are parameters, not decisions — a visual re-check at apply tunes the value, never the arithmetic.
- Pure module: no React, no DOM, no api types, no side effects. Integer px formatting only (`${n}px`), no decimal chrome math escaping into the strings.
## Acceptance
